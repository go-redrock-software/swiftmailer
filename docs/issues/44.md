# Issue #44: Bind API listeners with default constructor options

**Branch:** fix/44-bind-default-api-listeners

## Design

Lazily create a dispatcher on first plugin registration, preserving injected dispatchers and reusing the lazy instance. Bind once per registration call and retain the simple dispatcher's same-instance deduplication. Preserve no-plugin behavior. Verify default constructors across all 21 API transports for header/envelope blocking, redirect payloads, restoration and provider-failure cleanup. Check DSN construction and replace the old test that asserted registration must be a no-op.

Use mocked requests; run PHP 8.3/8.5 suites, PHPStan, full formatting and Composer validation. This stacks on #39 because SES previously did not dispatch send events at all. Calendar-audience draft #42 / !9 remains separate.

## Implementation

### Changes

- AbstractApiTransport::registerPlugin creates Swift_Events_SimpleEventDispatcher only when none exists, then binds the listener. This shared two-statement implementation covers all 17 HTTP and four SDK transports.
- ApiDefaultDispatcherTest adds a 127-scenario matrix: each of 21 concrete default constructors rejects blocked headers and blocked explicit envelopes; redirects both header and explicit-envelope provider payloads; restores recipients and caller envelopes; and reports only the redirected audience after provider failure. The DSN factory is checked separately.
- Payload checks use mocked HTTP clients, actual Google/Graph SDK serialization against local mock handlers, and SES request objects/arrays. Base64 MIME inputs are decoded for privacy assertions. No provider delivery or credentials were used.
- Observer checks prove one completion per send and preservation of simple-dispatcher deduplication for a repeated listener instance. Existing injected-dispatcher delegation test also checks object identity.
- Replaced the old null-dispatcher no-op expectation with initialization/reuse assertions. No-plugin lifecycle/error regression tests remain intact.
- Updated API, Graph and security guides plus CHANGES.

### Validation

- Initial 85-scenario matrix: 42 errors + 42 failures before the fix; the already-configured DSN case passed. All 85 passed after the fix.
- Expanded matrix (explicit-envelope redirects/failures, duplicate registration and decoded MIME checks): 127 tests, 1,195 assertions, pass.
- Full PHP 8.5: 4,432 tests, 27,259 assertions, 30 external-service skips, exit 0 with normal project deprecation policy.
- Full PHP 8.3: 4,432 tests, 27,242 assertions, 30 external-service skips, exit 0; two existing PHPUnit E_ERROR expectation warnings.
- PHPStan: no errors, no baseline expansion. Full formatter: 0 of 502 files need changes. Composer strict validation and git diff checks pass.

### Review Notes

Review relative to !7. This is independent of !9's Graph calendar recipient-audience work and does not resolve its concurrency gate. It makes previously ignored plugins active when directly constructed transports register them; applications that accidentally relied on the no-op now receive their configured callbacks. A supplied dispatcher is not replaced. No listeners or default safety policy are enabled unless the caller registers them or supplies a configured dispatcher.

Gmail's existing provider-exception behavior returns 0 rather than throwing; tests retain that behavior while verifying failure metadata and cleanup. The factory already injects dispatchers, so its construction logic needs no change.
