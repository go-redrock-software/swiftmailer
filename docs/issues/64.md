# Issue #64: Preserve MIME attachments in normal SES API sends

**Branch:** fix/64-preserve-ses-mime-parts
**MR:** Pending implementation
**Issue:** https://code.go-redrock.com/trac/swiftmailer/-/issues/64

## Design

## Implementation Plan

### Approach
Keep the existing SES Simple payload for messages without child MIME parts and without an explicit envelope. When a message contains attachments, inline parts or alternative bodies, select Content.Raw using the existing complete-message serialization helper that strips the Bcc header. Let AsyncAws encode the raw bytes once. Do not append child bodies manually.

### Changes
- Update getRequest in both SES transports to choose raw MIME before AsyncAws constructs the content model for child-bearing messages while preserving their existing FromEmailAddress, Destination (including Bcc routing), reply-to, feedback forwarding, SES configuration/identity/list-management and EmailTags fields.
- Keep explicit envelope handling authoritative. Source inspection confirms that both matching and differing explicit envelopes already select Raw; reuse already-rendered raw content for envelope sends, preserving one serialization and these control paths. A child-only message with no root body must avoid constructing invalid Simple content before Raw selection.
- Reuse the protected HTTP/credential operation policy unchanged. Keep API recipient counts and Http X-SES-Message-ID behavior; preserve normal error, policy and event handling.
- Document Simple versus Raw selection and replace the silent-loss proof with real serialized SDK regression coverage.

### Acceptance Criteria
- Real AsyncAws/Symfony fixtures for both transports show the attachment filename and exact decoded bytes in one raw MIME part; normal send returns the correct count. Cover binary and stream-backed attachments, inline Content-ID, text/HTML alternatives, multiple/nested parts and repeated sends without duplication.
- To/Cc remain visible, Bcc is routed through Destination but absent from raw headers, and the original message's recipient/body/child state is preserved (apart from established tag/header behavior). Verify both matching and differing explicit envelopes, bounce sender and attachment-bearing allowlist/redirect policies.
- Keep existing simple-message schema assertions, SES metadata/header mapping, response IDs and success/failure events. Redirect refusals stay permanent and cannot forward/retry attachment bytes.
- Verify the raw payload with the supported older SES SDK as well as current SDK fixtures. No dependency, vendor, baseline or threshold changes.
- Full PHP 8.3/8.5 suites, PHPStan, style, Composer and diff checks; final MR head must pass all six required CI jobs. Stack on !21. No merge is authorized by this plan.

### Risks
Raw MIME requires complete serialization, including signer behavior and stream consumption; reuse the existing helper and assert actual bytes instead of reconstructing MIME. Matching envelopes and repeated sends must not silently return to Simple, serialize twice or duplicate parts. The Http transport deliberately adds its response-ID header and tag extraction already removes tag headers; tests should preserve those established behaviors without claiming byte-for-byte message immutability across successful sends.

## Implementation

### Changes
- Both getRequest implementations select Content.Raw for child-bearing messages before constructing AsyncAws value objects. Normal messages no longer lose attachments, inline parts or alternative bodies. Child-only messages avoid the previous API failure from constructing Simple body Data=null.
- Explicit envelopes keep their independent Destination and feedback forwarding sender, reusing already-rendered Raw content. Messages without child parts retain the existing Simple payload unless an explicit envelope selects Raw. Complete MIME is serialized once, and AsyncAws performs the outer base64 encoding.
- Reused the existing separate MIME-copy helper, which strips Bcc/Resent-Bcc and internal tag/metadata headers. Native From/To/Cc, reply-to, MIME encodings, filenames, CIDs and child parts remain intact. SES configuration/identity/list-management/tags stay request fields.
- Added SesMimeDeliveryTest and updated the existing rich-message SDK schema contract to require Raw rather than asserting the attachment-losing Simple behavior. Existing simple-message tests continue unchanged. Updated provider documentation.

### Validation
- 64 new cases, 2,752 focused assertions. Against parent c3fb293a, the final suite has 16 failures and 10 errors, with 38 existing envelope/signer controls passing. Against the implementation all 64 pass.
- Cases cover binary, empty, array-stream and real file attachments; inline CID; alternatives; nested MIME; and child-only bodies. Normal/matching/differing-envelope cases send twice and compare every MIME byte except transient boundary names, while independently decoding attachment bytes and asserting no duplicate parts. Routing, SES fields, source-message state, allowlist/redirect policies, failure/completion events and permanent redirect refusal are checked. Real DKIM signers run once per send for each envelope mode.
- A native HTTP probe uses two ephemeral loopback servers, fabricated credentials and a real default SesClient for each transport. The first request contains one attachment with the exact decoded binary bytes, no MIME Bcc header, and the proper Bcc Destination. A 307 is refused permanently with one request; the second server receives none. Both servers are shut down. Evidence: /tmp/swiftmailer-64-native-probe.php/.py/.jsonl.
- 36 isolated older-SDK scenarios each send twice with SES 1.8.2, Core 1.9.2 and Symfony HTTP 4.4/contracts 1.1.13. Binary, stream, file, inline, alternative and child-only MIME all pass for both transports across all envelope modes. Evidence: /tmp/swiftmailer-64-legacy-probe.php/.jsonl. This reuses the old-version compatibility fixture, which has previously recorded upstream advisories; no project dependency or vendor change was made.
- Full PHP 8.5 composer test: 8,436 tests, 82,248 assertions, 30 existing skips. Full PHP 8.3: 8,436 tests, 82,244 assertions, two existing E_ERROR expectation warnings and 30 existing skips. Existing deprecation policy remains intact.
- PHPStan clean; full style check clean (527 PHP files); Composer validation and diff checks clean. No dependency, vendor, class-map, baseline or CI-threshold changes.
- Current official SES RawMessage documentation was fetched through Context7 first; installed current and older AsyncAws RawMessage serializers confirm SDK-owned base64 encoding. [AWS RawMessage contract](https://docs.aws.amazon.com/ses/latest/APIReference-V2/API_RawMessage.md).

### Review Notes
- Stacked on !21. Review MIME selection before SDK construction and Raw reuse for explicit envelopes: selecting Raw only after building the typed Simple model fails for child-only bodies, and rendering at both points would run signers twice.
- Bcc routing stays in Destination while MIME Bcc/Resent-Bcc headers are removed. Explicit envelopes preserve visible headers and use their own feedback forwarding sender. Raw serialization uses the existing complete-message helper; children are never appended manually.
- Successful Http sends still append X-SES-Message-ID and tag extraction still removes X-Mailer-Tag. Tests account for those established behaviors; no stronger message-immutability or header-deduplication claim is made.
- Fixtures verify serialized requests and MIME bytes, not delivery acceptance by a live AWS account. Provider identity and attachment-type/size rules remain provider-controlled.
