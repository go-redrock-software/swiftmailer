## Design

## Implementation Plan

### Approach
Introduce one stateless `Swift_Transport_RetryPolicy::isTerminalFailure(Throwable)` cause-chain check for explicit non-replayable markers and PHP Error causes. Reuse it in the default classifier, failover/load-balanced send/start catches, the retry loop before custom classification, and the retry-restart catch. Rethrow the original failure before stopping/removing a backend, sleeping, retrying or invoking another sender.

Check cleanup failures too: when stopping a failed backend raises a terminal error, propagate it before another delivery and restore the popped pool entry only if the remaining pool has not been replaced reentrantly. Ordinary stop exceptions retain current logging/fallback behavior. Direct PHP Errors remain terminal.

### Changes
- Add the shared retry-policy class and its generated-map/namespace alias entries.
- Update `DefaultRetryClassifier`, `RetryTransport`, `LoadBalancedTransport` and `FailoverTransport` without changing public constructor signatures or normal backend-specific failure classification.
- Add public-send regressions using real HTTP transports/synthetic endpoints plus focused instrumented transports for start/restart/cleanup and state/cause identity checks.
- Document hard terminal failures and custom classifier limits; update the #66 handoff and the existing threat-plan status only where demonstrated by this change.
- Base on !23 (`c25c22bb`); keep independent SES branches and retry-period features #29/#31 out of this change.

### Acceptance Criteria
- Failing-before evidence for real ambiguous 2xx, redirects and wrapped PHP Error causes through failover/load balancing/custom retry, including nested wrapper configurations, direct/deep markers, start/send/restart/cleanup phases and preserved original cause chains.
- Terminal paths make no later delivery request, do not call a custom classifier/backoff after the terminal failure, and retain the failing backend where it has not been replaced by newer caller state. Last-used transport is not stale.
- Ordinary transient failures, ordinary backend authentication failures, exhaustion, custom retry decisions, later explicit sends and rotation retain current semantics. Existing envelope, recipient policies, events and failed-recipient handling are covered at terminal boundaries.
- Full PHP 8.3/8.5 suites, PHPStan, style, strict Composer/map/alias/diff checks and six required CI jobs at the exact final MR head. No dependency/vendor/baseline/threshold changes. Observe optional CI limits accurately; no merge.

### Risks
Hard terminal causes cannot be overridden by permissive custom classifiers; document this deliberate safety contract. Preserve exception identity and pool state rather than replacing failures with generic exhaustion. Cleanup/reentrant configuration must not restore stale transports. Do not broadly apply default auth/status classification to failover, where a different backend may legitimately succeed.
