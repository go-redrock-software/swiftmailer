# Issue #66: Honor terminal failures across transport wrappers

**Branch:** fix/66-honor-terminal-transport-failures

**Issue:** https://code.go-redrock.com/trac/swiftmailer/-/issues/66

## Design

## Implementation Plan

### Approach
Introduce one stateless `Swift_Transport_RetryPolicy::isTerminalFailure(Throwable)` cause-chain check for explicit non-replayable markers and PHP Error causes. Reuse it in the default classifier, failover/load-balanced send/start catches, the retry loop before custom classification, and the retry-restart catch. Rethrow the original failure before stopping/removing a backend, sleeping, retrying or invoking another sender.

Check cleanup failures too: when stopping a failed backend raises a terminal error, propagate it before another delivery and restore the popped pool entry only if the remaining pool has not been replaced reentrantly. Ordinary stop exceptions retain current logging/fallback behavior. Direct PHP Errors remain terminal.

### Changes
- Add the shared retry-policy class and its generated-map/namespace alias entries.
- Update `DefaultRetryClassifier`, `RetryTransport`, `LoadBalancedTransport` and `FailoverTransport` without changing public constructor signatures or normal backend-specific failure classification.
- Add public-send regressions using real HTTP transports/synthetic endpoints plus focused instrumented transports for start/restart/cleanup and state/cause identity checks.
- Document hard terminal failures and custom classifier limits; update the #66 handoff and the existing threat-plan status only where demonstrated by this change.
- Base on !23 (`c25c22bb`); keep independent SES branches and retry-period features #29/#31 out of this change.

### Acceptance Criteria
- Failing-before evidence for real ambiguous 2xx, redirects and wrapped PHP Error causes through failover/load balancing/custom retry, including nested wrapper configurations, direct/deep markers, start/send/restart/cleanup phases and preserved original cause chains.
- Terminal paths make no later delivery request, do not call a custom classifier/backoff after the terminal failure, and retain the failing backend where it has not been replaced by newer caller state. Last-used transport is not stale.
- Ordinary transient failures, ordinary backend authentication failures, exhaustion, custom retry decisions, later explicit sends and rotation retain current semantics. Existing envelope, recipient policies, events and failed-recipient handling are covered at terminal boundaries.
- Full PHP 8.3/8.5 suites, PHPStan, style, strict Composer/map/alias/diff checks and six required CI jobs at the exact final MR head. No dependency/vendor/baseline/threshold changes. Observe optional CI limits accurately; no merge.

### Risks
Hard terminal causes cannot be overridden by permissive custom classifiers; document this deliberate safety contract. Preserve exception identity and pool state rather than replacing failures with generic exhaustion. Cleanup/reentrant configuration must not restore stale transports. Do not broadly apply default auth/status classification to failover, where a different backend may legitimately succeed.

## Implementation

### Changes

- Added the stateless `Swift_Transport_RetryPolicy` cause-chain check and class-map/namespace alias entries. The default classifier and all three wrappers share the hard terminal boundary.
- Failover and round-robin propagate terminal send/start errors before logging retirement, stopping a backend or trying another sender. Retry checks precede custom classification and terminal retry-restart errors are rethrown immediately.
- Terminal cleanup failures restore a popped backend only while the pool’s configuration counter and remaining entries still match. Raw PHP Errors also propagate. Ordinary cleanup errors retain the previous fallback/logging behavior.
- Pool replacements increment a configuration counter. A failure from an older attempt cannot retire a newly configured backend; callback replacements comparing equal to the remaining pool still take precedence.
- `FailoverTransport::setTransports()` clears its cached selection (#67). Its private cached transport has an explicit nullable native type matching its existing lifecycle. Historical last-success state is retained until the next send.
- Updated sending/DSN/API/security guidance and added a dated correction to the historical failover threat plan. Public constructor and protected lifecycle signatures are retained.

### Validation

- Initial real HTTP/lifecycle suite: **78 failures out of 112 tests** before implementation; the 34 controls passed. After the terminal fix, all 112 passed.
- Pool replacement: four additional failing-before failover scenarios; the same round-robin scenarios passed as controls. All eight pass after resetting cached selection.
- Configuration-counter hardening: two failing cleanup regressions and four failing ordinary-failure cases before correction. These verify equal-valued callback replacement and prevent an old failure from retiring a new backend.
- Final focused suite: **146 tests, 1,084 assertions**, all passing. Real Resend/Guzzle requests cover uncertain 2xx acceptance, redirect refusal and wrapped programming Errors across nested wrappers, implicit/explicit envelopes, recipient policies, failed-recipient references, message restoration and events. Observable fixtures cover deep/direct causes, startup, retry restart, cleanup, later deliberate sends, current-pool ownership, ordinary auth/transient fallback and permissive/restrictive custom classifiers.
- **14/14 focused manual mutations caught by assertion failures**, with no mutation execution errors. They remove individual wrapper/restart/cleanup guards, deep-cause/Error handling, restoration checks, cached-backend reset and pool-generation handling. Source snapshots were restored and reverified. This is a focused behavioral audit, not a global Infection MSI score.
- Standalone public-send probes confirm all 12 terminal wrapper combinations now make one primary request, no secondary request and propagate failure. The pool-replacement probe now makes one old-backend request and one replacement request, with the replacement recorded as last used.
- Generated class map exactly matches source: **231 entries**; the namespace alias loads. **Full suites: 7,899 tests on each runtime**. PHP 8.5: 74,248 assertions and 30 skips. PHP 8.3: 74,244 assertions, the two existing PHPUnit E_ERROR warnings and 30 skips. PHPStan, 523-file style, strict Composer validation and diff checks pass. Exact-head CI evidence will be recorded in the MR and linked issue notes after the final push.

### Review Notes

Hard terminal markers and PHP Error causes deliberately take precedence over permissive custom classifiers. Ordinary code/text classification remains configurable; ordinary backend-specific authentication failures can still fail over. A terminal message failure does not retire a backend. When callbacks replace a pool during an attempt, only remaining attempts in that send’s existing budget may use the new pool. This change does not add configurable retry periods, a minimum transport-security policy or random selection.

Based on !23 (`c25c22bb`), independently of SES !21/!22. No dependency/vendor/baseline/CI-threshold changes. Review remains independent; no merge authorized.
