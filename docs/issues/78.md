### Changes
- DSN credentials are required `ACCESS_KEY:SECRET`; preserve encoded and literal-zero opaque values. Optional SES-only `session_token` accepts nonempty visible ASCII, with no whitespace/control/header injection. Reuse canonical scalar/duplicate/name validation with configured query separators. Extend `region` scope to SES, default explicitly to `us-east-1`, validate ordinary AWS region-code syntax, and retain existing Mailgun/Scaleway behavior.
- Construct a real AsyncAws SesClient with explicit Credentials, configuration credentials, region, endpoint and debug=false. No ambient credential/provider/role/region/endpoint fallback. Default endpoints use the regional SES hostname (including standard GovCloud/China/Sovereign domain conventions); a custom DSN HTTPS authority/port/base path uses the existing public-endpoint guard and an explicit signing region. Region syntax does not guarantee that SES is available there. Default host disallows unused port/path/fragment overrides; custom endpoints retain fragment/path validation. Advanced FIPS can use an explicit endpoint host and its normal signing region.
- Add an optional sensitive `sesHttpClient` constructor parameter to DsnTransportFactory for caller-owned Symfony HTTP clients used by its SES clients. Omission retains AsyncAws's normal HTTP/retry construction; injected clients retain their configuration and lifetime. Reuse the dependency's operation-local HTTP/credential policy without bypass hooks or fake SDKs.
- Remove SES from the unsupported-SDK rejection list only after explicit client construction is implemented. Google and Graph remain safely rejected. Keep missing SES credentials rejected before network/SDK construction. Retain public helper, retry/pool composition, recipient/event/attachment/redirect policies.
- Add real AsyncAws signed/serialized wire tests with synthetic Symfony handlers: region/host/session credentials, independent SigV4 verification, ambient isolation, wrappers/helper, event wiring, raw MIME/envelopes and permanent redirects. Invalid DSN/schema/scope/query/trace privacy regressions remain network-free. Update documentation and #30's open requirement map.

## Implementation

### Changes and Dependencies

- Both SES DSN schemes now construct a real AsyncAws SesClient using required access-key/secret, explicit region/endpoint/debug settings and an immutable Credentials provider. Optional session_token and literal/encoded zero credentials reach actual SigV4 requests. Canonical scalar/name/duplicate validation uses PHP's query separators; invalid scopes, region syntax and credential control characters reject before requests.
- Added optional sensitive sesHttpClient constructor injection for factory-created SES clients. Injected clients retain configuration/identity/lifetime; omission keeps native AsyncAws HTTP/retry construction. Custom HTTPS authority/port/base paths use the existing public-address guard; defaults use regional domain conventions. Region syntax is not an availability catalogue; managed/ambient credential DSNs remain open design work under #30.
- Explicit local dependency merge **51b46413** integrates !21/#59/#63 and !22/#64 on top of !31, without conflicts. Their GitLab MRs remain open and unmerged. Those prerequisites provide credential/HTTP operation isolation, permanent redirects, valid health probes and complete MIME. No unrelated CI bootstrap changes were imported. Review feature changes relative to that merge to isolate the new implementation.
- During error-path audit, confidential #79 exposed credential-bearing SDK exception graphs. Native SES sends now return static Swift failures with safe status and terminal markers, without original SDK message/cause. Sensitive callable/error inputs protect local trace arguments. PHP Error causes remain terminal; connection and 429/500/502/503/504 failures retain transient classification. This intentionally changes callers that inspect SDK-specific causes; generic Swift cause support is unchanged.
- #80 prevents SDK coercion of malformed MessageId fields into false acceptance. SendEmail 2xx JSON must contain a nonempty string ID without whitespace/control characters. String 0 is valid. Missing/invalid IDs, malformed JSON and interrupted 2xx bodies are permanent acceptance ambiguities, including through forced retry/pool classifiers. Refusals latch within one operation and do not poison later explicit sends. Health/credential/error responses retain normal SDK handling. Explicit exception-event cancellation remains supported.
