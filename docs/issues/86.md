## Design

## Implementation Plan

### Approach
Validate raw operation-specific Graph acceptance before Kiota coercion, within the existing isolated Guzzle guard and before caller/SDK retry middleware can replay a response. Keep SDK authentication/serialization/parsing/CAE and caller HTTP ownership. Use one policy per Swift send, explicit operation boundaries, permanent ambiguity latching and post-SDK acceptance checks; reentrant/new sends must have independent state. Detach any permanent refusal through the existing safe Graph failure boundary.

### Changes
Cover sendMail and draft send (202 empty response), draft/small attachment/event creation (201 with typed nonempty IDs), event update (200 with typed ID), event lookup (200 with a valid event collection; missing/malformed entries cannot mean no match), upload-session creation (201 with usable URL/expiry/initial range), and sequential upload chunks (200 progress range, 201 final Location completion). Verify statuses/fields against official current Graph contracts. Preserve documented Outlook empty-body final uploads and SDK parsing of valid models. Correct old synthetic upload fixtures that used undocumented 202 progress or omitted completion evidence, with deliberate compatibility notes. Stop malformed/incomplete/interrupted 2xx responses and post-success parsing failures permanently, including response-bearing rejected transfers, sticky middleware retries, Swift retries and pools. Keep ordinary non-success status/CAE/transient behavior unless a prior accepted notification makes replay unsafe. Audit compound operations for partial notification success before a later failure.

### Acceptance Criteria
Real GraphServiceClient/GraphRequestAdapter/Guzzle fixtures fail before fixes for each confirmed route. A malformed lookup never creates an event; incomplete draft/attachment/session/chunk results never continue or recreate drafts; ambiguous mail/event sends never report success or replay. Valid documented no-content/model/session/multi-chunk flows work, including nonseekable streams. Preserve numeric status, safe detached diagnostics, argument-recording privacy, lifecycle/failed-recipient/message restoration, envelope/policies/caller objects and separate reentrant/reset state. Exercise caller/SDK retry and Swift retry/failover/round-robin, ordinary status/network/CAE controls and focused manual mutations. Full PHP 8.3/8.5, PHPStan/style/strict Composer/generated map/aliases and exact-final-head required CI; record optional CI accurately. No dependency/vendor/baseline/threshold changes or GitLab merges.

### Risks and Sources
Stricter success/acceptance rejects previously tolerated invalid provider responses and invalid synthetic fixtures. Graph 202 means accepted for processing, not guaranteed delivery. Outlook upload completion uses a Location header and may have no JSON body; do not substitute a model-ID requirement for this documented response. Do not expose opaque upload URLs, provider bodies or SDK graphs. Keep broader Graph DSN and managed-credential work under open #30. Current Context7 SDK/contracts, official Graph operation docs and installed Kiota/LargeFileUploadTask source guide the implementation. Base is ready, unmerged !35 (`e336569e`).

### Initial proof

A real GraphServiceClient/GraphRequestAdapter/Guzzle synthetic probe on the #84/#85 branch returns HTTP 201 with `{}` for draft creation. With a large attachment forcing the draft flow, Swift_Transport_RetryTransport(maxRetries: 2) issues three POST /v1.0/me/messages requests, then reports code 0, terminal=false and retryable=true. Each earlier 201 may already have created a draft, so replay is unsafe after unconfirmed successful operation results. The failure-privacy/status changes do not resolve this separate acceptance ambiguity.

Reproduction uses Swift_GraphSdkFixture with a canned 201 JSON response, native MicrosoftGraphTransport threshold 16, a 32-byte attachment and the default retry wrapper. No real credentials/provider request or accepted delivery was used. Authoritative local evidence: /tmp/swiftmailer-86-proof.json.

## Implementation

### Changes

- Added GraphAcceptancePolicy with one fresh instance per Swift send and explicit boundaries for all ten Graph mail/draft/attachment/upload/calendar stages. Raw success is checked in the isolated Guzzle guard before caller/SDK retry middleware and before Kiota coercion. SDK models must agree with raw typed metadata; metadata getters/parser failures after successful headers become permanent, safely detached failures.
- No-content actions require 202/empty body; creation requires 201/typed ID; event updates require 200/the requested ID; lookups require a valid event collection. Empty pages follow same-origin/same-path HTTPS continuation URLs, with query and loop validation before any event mutation. Ordinary status/CAE/transient behavior is preserved before notification acceptance.
- Upload sessions require usable opaque HTTPS URLs, unexpired ISO timestamps and initial byte-zero ranges. Parsed URL/expiry/range metadata must agree with raw evidence. Canonical URI comparison preserves host/default-port normalization and opaque queries. Sequential chunks require 200/exact forward progress and final 201/Location at the final byte; an empty final body is normalized for Kiota's model parser. Existing real SDK tasks remain responsible for serialization, chunking and parsing.
- Acknowledged requests cannot be replayed by caller middleware. Ambiguous responses are sticky across replacement errors, rejected synchronous/asynchronous transfers, SDK/caller retries and Swift retry/failover/round-robin. A later failure after accepted event create/update/cancel cannot replay earlier notifications. Reentrant/new sends remain independent; suppressed local preflight errors cannot masquerade as accepted mail.
- Updated minimum response fixtures explicitly: old 202 upload progress becomes documented 200, final upload fixtures supply Location, and successful PATCH/no-content fixtures use the correct status/body. Six mocked draft/calendar delivery seams and the draft routing test now exercise real GraphServiceClient/GraphRequestAdapter/Guzzle and actual upload tasks. No fake SDK client/bypass hooks were introduced to claim successful delivery.
- Added the class map and namespace alias, and updated API/security/Graph docs. Corrected stale claims that calendar matching used iCalUId/transactionId. This targets ready, unmerged !35; #30 stays open.

### Validation

Earlier standalone proof created three synthetic drafts for HTTP 201 `{}`. Additional focused proofs exposed unprocessed pagination (five failing assertions after the initial adapter), changed parsed expiry (one assertion failure), and mismatched updated-event identity (one assertion failure).
- **466 new cases**: 426 operation/metadata/continuation/lifecycle/ownership controls plus 40 isolated real OAuth acceptance privacy cases, with argument recording and Guzzle error handling enabled/disabled. All ten stages cover malformed/missing/coerced JSON, wrong successful status, interrupted bodies, rejected transfers and Swift delivery wrappers. Valid controls cover nonseekable bodies, session timestamp/range variants, opaque URLs, sequential multi-chunk upload and final empty-body Location acknowledgements. Shared and legacy controls retain policies/envelopes, CAE/native retries, events, failed recipients and caller objects.
- Final acceptance suite: **426 tests / 4,351 assertions**. Full PHP 8.3: **10,975 tests / 107,893 assertions / 30 skips**, with the two existing PHPUnit E_ERROR/E_USER_ERROR expectation warnings. Full PHP 8.5: **10,975 tests / 107,900 assertions / 30 skips**. Both pass and include all final Graph/Gmail/shared-policy and legacy controls.
- **29/29 focused manual mutations** detected by assertion failures, with no bootstrap errors; source snapshots restored after every run and final cleanup. Cover raw callback/innermost guard, post-parser models/expiry/status, sticky failure/notification/reset, typed IDs, paging/cycles, URL/expiry/initial and progress ranges, final status/Location, update identity, mail completion and unsafe SDK causes. A range-type mutation initially survived because downstream SDK/completion checks also refused it; parser-call assertions now prove rejection before SDK parsing. This is not an Infection MSI result.
- PHPStan, **558-file** style dry-run, strict Composer, generated **238-entry** class map, four relevant namespace aliases and whitespace checks pass. Exact-final-head CI is recorded on GitLab. No dependency/vendor/baseline/threshold changes. No real credentials or provider requests were used.

### Review Notes

Stricter success contracts intentionally reject previously accepted invalid provider/fixture responses. Numeric status and terminal markers remain available through the detached boundary; provider messages/causes and opaque upload URLs remain unavailable. HTTP 202 is processing acceptance, not final delivery. Notification success followed by a later failure is terminal even if that later error alone would be transient. Preparatory success alone does not turn later ordinary failures into notification ambiguity. New sends remain explicit caller decisions; this adds no durable deduplication or live-tenant delivery proof.

Review scoped policy/adapter associations, parser agreement, sequential upload state, safe opaque pagination and notification state carefully. No dependencies/vendor files, suppression baselines or thresholds change. #30's Graph DSN and managed-credential work remains open; no GitLab MR is merged.
