## Design

### Approach
Branch `fix/58-isolate-graph-sdk-requests` from !18 at `b4c056cce2152336ecdeb1c0f08985c424d73d67`, reusing its operation-scoped NoRedirectClient and existing non-retryable marker. Protect all Graph resource requests made by a public Swift send, including draft attachment uploads and calendar operations, while leaving the caller Graph client/adapter/HTTP configuration intact.

The installed Kiota GuzzleRequestAdapter has no public getter/setter/factory for replacing only an already configured HTTP client. Its typed RequestInformation options cannot directly carry ordinary Guzzle redirect options. Rebuilding authentication/serialization manually would discard configured behavior. Use one checked compatibility helper that clones a standard GuzzleRequestAdapter and replaces only the copy's private guzzleClient field with NoRedirectClient via ReflectionProperty. Retain the original authentication provider, serialization/parse factories, telemetry/tracer, CAE logic, base URL and cache objects. Build operation-local generated request builders from that adapter. No caller-owned object is temporarily rewritten. Unsupported/non-cloneable/uninitialized adapters must fail clearly with the non-retryable marker before network traffic; future SDK field changes fail closed.

A local real-SDK probe confirms this boundary: previously Graph send followed 307 and reported two accepted recipients; the cloned adapter now issues one request and raises a Swift transport exception wrapping the non-retryable marker. The original HTTP object, full defaults and handler-stack string remain identical.

### Changes
- Add a small Graph adapter compatibility helper and metadata/alias registration. Keep vendor-private access in one documented place with explicit checks and tests.
- Resolve mail and calendar user builders using the scoped adapter; cover sendMail, draft creation, small attachments, upload-session creation, draft send, event lookup/create/update/cancel.
- Ensure LargeFileUploadTask uses the same operation adapter and redirect latch. Preserve existing protected helper signatures/subclass hooks; use request/session identity to carry context without a globally swapped caller client. Keep callbacks, events, explicit envelope policies and cleanup on the original Swift transport.
- Retain ordinary SDK response decoding, authentication (including CAE), retries and success counts. The existing Graph exception wrapper may retain the marker in its cause chain; default Swift retries must not replay redirects. Health ping is local-only, so it must remain network-free.
- Replace affected builder-mock send assertions with real SDK/HTTP fixtures, preserving their behavioral coverage. Add failing-before/fixed-after real middleware tests covering all redirect statuses, destinations, default and caller retry middleware, draft/upload/calendar stages, success/error controls, caller state, reentrancy and policies.
- Document the compatibility boundary, generated-builder behavior and independent SDK scope. Graph OAuth token requests use a separate HTTP client and are not covered by swapping the resource adapter; assess independently and track a separate confirmed finding if needed. SES #59 remains separate.

### Acceptance Criteria
- With redirect-enabled injected defaults, every Graph resource request stays at its original target; no follow-up request or automatic Swift/SDK replay occurs on 3xx. No redirected send reports accepted recipients.
- An interrupted draft/upload/calendar flow sends no later dependent requests. Successful large attachment and calendar flows still work through real SDK serializers/adapters.
- Original Graph client/adapter identity, HTTP defaults/stack, base URL, auth provider/cache and unrelated subsequent caller requests retain their behavior. Callback/event transport identity remains the original Swift instance; policy-modified recipients are restored on all exits.
- Supported real Guzzle adapters preserve authentication/CAE and ordinary retry/error behavior. Unsupported adapters fail before wire requests. Custom adapters/SDK overrides are documented precisely rather than silently bypassing policy.
- Local-only ping stays network-free. No OAuth-wide or all-SDK guarantee is claimed without evidence.
- Full PHP 8.3 and 8.5 suites, PHPStan, full style, strict Composer validation, whitespace checks and exact-final-head required CI pass. No baseline/threshold/vendor edits; publish a reviewable MR targeting !18, update the board and do not merge.

### Risks
Private Kiota field access is a compatibility constraint, bounded by instance/field/type/clone checks and fail-closed tests. Standard adapter subclasses retain their state, but arbitrary overrides must honor the Guzzle/SDK contract. Caller custom GraphServiceClient builder overrides are not reproduced when standard operation-local generated builders are created; document this supported contract. Protected upload helper signatures remain intact. Resource requests and OAuth token exchanges have separate HTTP ownership boundaries; do not conflate them. Optional CI prerequisites #38/#40/#45/#46 remain separate.

## Implementation

### Changes and approach
- Added `Swift_Transport_Api_GraphRequestPolicy`: clone a supported Kiota GuzzleRequestAdapter and replace only the copy's HTTP client with the scoped NoRedirectClient from !18. Keep the private-field dependency centralized; check adapter type, cloneability, field presence, initialization, mutability and HTTP interface. Unsupported cases fail before requests.
- Graph user builders now use that operation-local adapter through the standard SDK factory. The original Graph client/adapter remain the API connection seen by callbacks and events. Shared authentication objects, serializer/parse factories, CAE, tracing, base URL and normal retry middleware are retained.
- Added builder/session identity maps to carry the same adapter into the existing protected draft/upload helper signatures. Session context is restored in finally, including reentrant calls. No caller SDK field or global client configuration is temporarily swapped.
- Registered native metadata/runtime alias. Generalized the shared HTTP guard's configuration error text from Google to SDK, without changing its behavior.
- Converted 35 affected Graph public-send tests from mocked builder chains to real generated SDK builders, serializers and offline HTTP fixtures. Preserved their assertions for recipients, names, attachments, alternatives, mailbox routing, calendar create/update/cancel, notices and counts; strengthened them with actual HTTP method/path checks. Protected helper/unit tests remain separate.
- Added a shared synthetic Graph HTTP fixture and 427 regression cases. No vendor files, baselines, mutation thresholds or unrelated alias-generator changes.

### Validation
- Before implementation, all 400 redirect matrix cases failed. After the scoped adapter change, all 400 passed (8,240 assertions). Matrix: five redirect statuses, four targets, ten resource stages and optional caller retry middleware, through real Graph/Guzzle middleware and default Swift retries.
- Added controls for 300/304/305/306/399 without Location, multi-chunk binary upload and content ranges, CAE claims replay, ordinary SDK 503 retry/403 decoding, unsupported adapters, national-cloud base URL/factories, network-free ping, policy/envelope cleanup, fresh sends after a redirect and original caller redirect behavior.
- Reentrancy control triggers a nested redirected send while the outer operation is uploading a chunk. The inner operation fails without poisoning the outer adapter/latch; the outer draft completes. Events and API connection retain original transport/client identity.
- Full PHP 8.5: 7,116 tests / 65,201 assertions / 30 skips. Full PHP 8.3: 7,116 tests / 65,192 assertions / two known E_ERROR expectation warnings / 30 skips.
- PHPStan, full style (514 files), strict Composer validation and whitespace checks pass. Exercised SDK chunk paths emit vendor integer-header deprecations; no baseline edits. Final-head required CI is recorded in the MR readiness note.
- All provider HTTP is synthetic/in-memory; no real email, provider request or credential is used. The large-upload control uses a local 4 MiB-plus-two-byte fixture to exercise two actual SDK PUTs.

### Independent authentication assessment
- Confirmed confidential #60: the real GraphPhpLeagueAccessTokenProvider's default OAuth HTTP configuration follows a 307 and forwards the client_secret POST body to another origin. Public send still reports accepted mail afterward, including with this resource guard enabled. The token and resource clients have separate HTTP ownership.
- The probe preserves the default OAuth configuration and replaces only its physical handler with two in-memory responses; all tenant/client/secret values are invented. The real SDK auth provider and resource adapter are used. Portable code and observed output are attached to #60.
- #60 requires a separate operation-scoped OAuth policy, preserving refresh/cache/CAE/custom-provider behavior. #59 remains the separate SES finding. This MR deliberately makes a resource-request claim, not an all-SDK or OAuth-wide guarantee.

### Review notes
- The vendor-private `GuzzleRequestAdapter::guzzleClient` dependency is a checked compatibility constraint. Current Graph 2.56.0 / Kiota HTTP 1.5.2 were inspected directly; unsupported layouts fail closed. [SDK custom-client documentation](https://github.com/microsoftgraph/msgraph-sdk-php/blob/main/docs/authentication_samples.md) and [request/retry examples](https://github.com/microsoftgraph/msgraph-sdk-php/blob/main/docs/general_samples.md) were retrieved with Context7; they provide construction hooks, not a public replacement hook for an already configured adapter.
- Standard operation-local generated builders do not reproduce caller GraphServiceClient builder-method overrides. Custom adapter subclasses must honor their inherited HTTP contract. The original client remains available unchanged to callers.
- Review handler ordering/latching, preserved auth/serialization ownership and upload context cleanup. Shared HTTP middleware is retained; arbitrary custom HTTP-client method overrides are not copied, as documented for !18.
- Stacked on !18. Optional CI prerequisites #38/#40/#45/#46 remain pending integration. No merge performed.
