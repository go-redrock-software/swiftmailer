## Requirements audit and implementation map

The original #30 requirements remain the scope of this umbrella issue. Current evidence at !28 (`36cc7e08`):

| Requirement | Evidence/status |
| --- | --- |
| Defined DSN format, credentials/host/port/options | `doc/dsn.md`, readonly `Swift_Dsn`, encoding tests; SMTP/sendmail/null and constructible HTTP schemes exist. |
| Parsing and connection factory | Operational `DsnTransportFactory`, public helper repaired by #71 / !28; metadata helper remains distinct. |
| Authentication, encryption, timeout and protocol decorations | TLS/source-IP/UTF8 and retry/pool options exist; `timeout`, `auth_mode`, `local_domain` are currently warned about and ignored. Implementing these in #72. Literal-zero SMTP credentials are lost by truthiness; #73 covers the related end-to-end AUTH repair. |
| Provider/SDK construction | Several registered schemes still require manual SDK/client/extra constructor arguments and currently lack complete DSN construction. Keep this design/implementation phase open, including explicit credential/configuration contracts and caller-owned client handling. Do not count registered class-map entries as proof of construction support. |
| Documentation | Existing factory/provider tables distinguish construction limits; #72 updates new options and the final audit must reconcile every supported route. |
| Tests/security | Current suites pass; add real loopback configuration/AUTH/timeout coverage in #72/#73. Retain input validation, own-frame redaction and existing recipient/redirect policies; broader factory security/unsupported-route behavior remains part of the audit. |

#72/#73 are concrete next deliveries, based on !28. Their implementation will not by itself close #30. This map preserves the remaining provider/SDK scope rather than treating the available class map or current passing tests as completion. No merge.
