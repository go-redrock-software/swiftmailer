## Current phase

#72/#73 add SMTP timeout, authenticator selection and EHLO identity controls, with an operational compatibility adapter for literal-zero credentials in Nyholm 2.0.1 and the native AUTH truthiness repairs. See the shared [#72 handoff](72.md). The raw metadata helper still retains the dependency's representation; provider/SDK construction and the rest of this audit remain open. This phase does not close #30.

Current implementation review: [!29](https://code.go-redrock.com/trac/swiftmailer/-/merge_requests/29), covering #72/#73.

## HTTP provider construction phase (#74/#75)

[#74](74.md) implements Mailgun, Mailjet, Scaleway, Infobip, Postal and live Mailtrap constructor contracts, validates scoped region/inbox options and custom HTTPS endpoint fields, and preserves zero API credentials. SDK schemes reject before receiving a raw credential as a client; explicit SDK client/authentication DSNs remain future work. This phase does not close #30.

## Parser and CLI diagnostic privacy (#76/#77)

[#76](76.md) replaces credential-bearing parser failures at operational and metadata boundaries, without retaining unsafe causes. #77 removes the CLI raw/partially masked DSN preview. Successful parser grammar and metadata remain unchanged. SDK authentication/client construction and the remaining requirements audit keep #30 open.

## Amazon SES SDK construction (#78)

[#78](78.md) constructs both SES SDK clients with explicit credentials, session-token/region and guarded endpoint contracts, while preserving caller-owned HTTP, native request isolation and complete MIME. Its local integration carries !21/!22 as dependencies on top of !31; those GitLab MRs remain unmerged. Google/Graph SDK construction, advanced ambient/managed credential DSN contracts and the remaining metadata/options audit keep #30 open.

The #78 phase also fixes confidential #79 (credential-bearing SES error graphs) and #80 (SDK acceptance coercion). Returned failures now retain safe status/terminal classification without unsafe SDK causes, and malformed/missing acceptance IDs are permanent ambiguities. Existing exception-event cancellation remains supported.

## Gmail acceptance and diagnostic audit (#81/#82)

[#81](81.md) validates successful Gmail send JSON before SDK model hydration and
requires an observed valid message ID before reporting recipients as accepted.
It makes malformed, missing or interrupted acceptance permanent and prevents
automatic replay through SDK/caller middleware and Swift delivery wrappers.
Confidential #82 detaches OAuth-bearing terminal exception graphs. Ordinary SDK
errors retain zero returns; HTTP ownership, token refresh and complete MIME stay
covered. This audit precedes Gmail DSN construction; Google/Graph construction
and the remaining requirements above keep #30 open. No GitLab MR was merged.

## Gmail SDK DSN construction (#83)

[#83](83.md) constructs real Gmail clients from explicit bearer tokens or renewable
OAuth client ID/secret/refresh-token DSNs. It pins standard Google endpoints,
universe and gmail.send scope, excludes ambient credentials, and preserves caller
Guzzle ownership. An SDK credential adapter retains literal-zero form fields and
native refresh/cache/response handling. Native MIME/policy/event/redirect/acceptance
and diagnostic boundaries remain in use. Graph construction, advanced managed
credential DSN contracts and the remaining audit keep this umbrella open. No
GitLab MR was merged.

## Graph failure boundary audit (#84/#85)

[#84](84.md) detaches unsafe Graph SDK failure graphs. #85 preserves actual Kiota
and OAuth HTTP statuses so default retry does not treat final auth failures as
connection failures. SDK parsing, token/context/cache ownership, lifecycle cleanup
and hard refusal/Error markers remain covered. [#86](86.md) records a separate
confirmed successful-draft ambiguity: missing IDs cause repeated draft creation.
Graph acceptance, DSN construction and the remaining original audit keep #30 open.
No GitLab MR was merged.
