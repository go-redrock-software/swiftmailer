## Design

## Implementation Plan

### Approach
Repair the public DSN convenience helper by delegating transport construction to `Swift_Transport_DsnTransportFactory::fromDsnString()`. Preserve its existing intended return value, a configured `Swift_Mailer`, and document the legacy naming. Link this focused bug to #30 without treating it as completion of that broader feature.

### Changes
- Replace the nonexistent metadata-parser method call with the operational factory; keep the existing mailer construction. Keep native parameter/return signature compatibility, add a sensitive-parameter attribute and a clear `@return Swift_Mailer` contract.
- Remove the dead-code coverage exclusion. Keep the metadata parser's role and existing DSN syntax/validation/decorator limits unchanged.
- Add failing-before public regression tests for actual null delivery, SMTP/TLS configuration without connecting, retry/pool wrapper composition and settings, SendGrid options and synthetic API sends, explicit envelopes/recipient policies/events, repeated independent construction and matching factory validation failures.
- Check that rejection traces redact this helper's own credential-bearing input. Existing factory exceptions propagate without a new wrapper or weaker validation.
- Update DSN, architecture and upgrade guidance: the legacy helper returns a mailer; the factory returns a transport. Add the committed handoff and link the MR.

### Acceptance Criteria
- `Swift::createTransportFromDsn('null://default')` returns a working mailer rather than PHP Error; direct factory behavior remains available and unchanged.
- SMTP settings and nested retry/pool/leaf options reach the configured backend. New mailers own independent transport instances. Unsupported/invalid configurations retain factory rejection behavior, including the sendmail allowlist and strict pool/SendGrid options.
- Public sends honor explicit envelopes and registered recipient policies, dispatch events and restore caller messages; no production provider request or SMTP/sendmail delivery occurs in tests.
- Privacy checks cover the helper's own trace argument on factory validation errors. No claim is made that all third-party parser errors are globally redacted.
- Focused/full PHP 8.3/8.5 suites, PHPStan, style, Composer/map/alias/diff checks and six required exact-final-head CI jobs pass. Record optional CI bootstrap/deprecation limits accurately; no dependency/vendor changes, added baseline suppressions, threshold relaxations or merge. Remove only the resolved undefined-method baseline entry.

### Risks and Decisions
The legacy method name suggests a transport, while its original implementation returns a mailer. Preserve that intent and document it explicitly rather than changing the return kind or adding a separate public API. Keep the native return type absent to avoid breaking subclasses that override the existing static method. This is a project-source delegation repair and uses existing local factory contracts; no new library API or dependency is introduced. Base on !27 to retain validated DSN/pool and recipient-security behavior.

## Implementation

### Changes

- `Swift::createTransportFromDsn()` now asks the operational factory to construct a transport and retains the original `new Swift_Mailer($transport)` return. Native parameter/return signature compatibility is preserved; PHPDoc clearly identifies the intended mailer return and direct-factory alternative. Its DSN argument is sensitive in the helper's own trace frame.
- Removed the dead-code coverage exclusion and the single resolved PHPStan `method.notFound` baseline entry for the nonexistent metadata-parser method. No suppression was added, no unrelated baseline entry was regenerated and no threshold was relaxed.
- Added public helper behavior regressions and updated DSN, architecture and upgrade guidance. Metadata parsing remains independent. No new public API, dependency, transport policy or provider constructor behavior is introduced.

### Validation

- Before repair: the standalone null helper probe throws the documented undefined-method PHP Error. New regression run: **29 cases, 19 errors and 10 assertion failures**, all failing. After repair: **29 tests / 223 assertions**, passing.
- Public sends cover null delivery with implicit/explicit envelopes, SMTP/plain/STARTTLS/SMTPS/provider settings without connecting, six decorator configurations and independent repeated construction. Six real Guzzle/synthetic-response cases combine outer retry, failover, per-leaf retry (two transient errors then success), SendGrid tracking, allowlist/catch-all/redirect policies, implicit/explicit envelopes, send events, client ownership and message restoration.
- Eight rejection cases match the direct factory's exception class and message, including unsafe sendmail binaries, unknown schemes, malformed input, strict cooldown/duplicate options and unsupported tracking. Two privacy cases inspect only the helper's own rejection-trace frame. No production provider request or SMTP/sendmail delivery occurs.
- **5/5 focused manual mutations detected by assertion failures**, sometimes with additional type/wire errors: return a transport, ignore the caller DSN, discard query/decorator options, swallow factory rejection, and expose the helper argument. Original source restored; this is not an Infection MSI score.
- Focused helper/core/factory/SendGrid run: **230 tests / 1,050 assertions**, passing. Full PHP 8.5: **8,201 tests, 76,454 assertions, 30 skips**. Full PHP 8.3: **8,201 tests, 76,449 assertions, two existing PHPUnit E_ERROR warnings, 30 skips**.
- PHPStan passes after removing the obsolete baseline entry. 528-file style, strict Composer validation and diff checks pass. Generated class map agrees exactly at **231 entries**, and mailer/transport namespace aliases are verified. Dependency/vendor files and thresholds are unchanged. Exact-final-head CI results will be linked from the MR and issue notes.
