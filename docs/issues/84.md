## Design

## Implementation Plan

### Approach
Detach Graph SDK send failures at the existing catch boundary into static Swift failures with safe numeric HTTP/exception metadata and no unsafe SDK message/previous cause. Preserve terminal markers and PHP Error causes using a nonretryable Swift class. Read Kiota ApiException responseStatusCode and Guzzle response status before falling back to safe numeric exception codes, including nested failures. Preserve HTTP 500 transient classification with a static internal-server-error phrase. If metadata inspection itself fails, refuse permanently rather than exposing the new SDK error.

### Changes
Add a focused failure adapter to GraphRequestPolicy and replace the unsafe MicrosoftGraphTransport catch wrapper. Update legacy tests deliberately for detached diagnostics and corrected 401/403 retry decisions; keep generic Swift cause support and existing event/cancellation semantics. Add isolated graph/message/trace privacy tests across real OAuth contexts and resource/token failures, advanced Graph stages, default and forced retry controls, safe nested metadata and caller ownership. Update API/security docs and #30's prerequisite audit map.

### Acceptance Criteria
Real Microsoft Graph/Kiota/League/Guzzle fixtures reproduce unsafe graphs/provider messages and lost Kiota HTTP codes before the fix. Messages, string traces and printed exception objects must not retain fabricated credential/provider markers with argument recording on/off. Correct status/terminal/default retry results for resource and OAuth failures; default auth failures do not automatically resend. Existing SDK retries remain functional. Redirect/Error hard failures cannot lose their marker after detachment, including across wrappers. Draft/upload/calendar paths, completion/failed-recipient cleanup and caller clients/options remain intact. Full PHP 8.3/8.5, PHPStan/style/Composer/map/alias checks, focused manual mutations and final-head required CI pass; optional results recorded accurately. No dependency/vendor/baseline/threshold changes or GitLab merges.

### Risks and Sources
SDK-specific messages/previous causes intentionally change to protect OAuth credentials; use safe Swift codes/terminal classification instead. Shared classifier rules outside this status-loss bug remain unchanged. Caller-owned trace frames/callback logging remain caller-controlled. Graph DSN construction and its acceptance audit remain open under #30; this work supplies a safe failure prerequisite. Context7 official Graph PHP documentation and installed Kiota ApiException/Guzzle adapter sources establish responseStatusCode versus Exception code semantics.

## Implementation

### Changes

- Graph SDK operation failures now detach through GraphRequestPolicy into static Swift transport failures without SDK messages or previous causes. Existing hard refusals and PHP Error causes become direct Swift_Transport_NonRetryableException markers. Generic Swift cause support remains unchanged.
- Safe numeric metadata prefers Kiota ApiException responseStatusCode, Guzzle response status and explicit redirect markers over ordinary exception-code fallback, including nested failures. HTTP 500 receives a static internal-server-error phrase to preserve the shared classifier's transient HTTP behavior. Failed metadata inspection returns a permanent safe failure.
- The operation-local Guzzle guard records response status before SDK decoding, clears it before new requests/authentication and handles response-bearing synchronous/asynchronous rejections. Graph OAuth carries observed error status through League's code-zero exceptions until the outer send detaches them. SDK parsing, callbacks/cache/context publication and caller HTTP ownership remain in use. Rejected 3xx responses retain hard refusal markers.
- Legacy cause/zero-status assertions were updated explicitly for detached diagnostics and corrected status/classification. Normal native SDK retries, token fallback/CAE flows and lifecycle cleanup remain covered. Updated API/security/Graph guides and #30's audit map.
- Separate #86 is recorded in needs-design with a real SDK proof: a successful draft response missing its ID causes three automatic draft-creation attempts. Graph acceptance and DSN construction remain open; this change does not claim to close that gap.

### Validation

- Real client-credential Graph/Kiota/League/Guzzle standalone probes showed provider-message leaks and credential-bearing printed exception graphs. The Kiota path produced Swift code 0 despite responseStatusCode 403, making default retry treat an auth failure as a connection error. Both client-secret/access-token markers were verified separately from provider diagnostics. No real credentials/provider request was used.
- Initial isolated regression suite: **296 tests / 296 assertion failures** before the boundary change. Token failures additionally exposed League GenericProvider's discarded HTTP status; operation-local status recording fixes that path instead of weakening its expectations.
- Final additions: **422 cases** — 383 isolated wire/diagnostic/lifecycle cases and 39 metadata/transient/state controls. Cover three real OAuth contexts, Guzzle-versus-Kiota error handling, argument recording enabled/disabled, ordinary auth/rate/server/network errors, message/token redirects, rejected transfers and token body PHP Errors. Advanced cases reach all ten mail/draft/upload/calendar stages. Default auth retries stop after one attempt; forced retry/failover/round-robin retain hard markers. Inspect messages, strings, traces and full printed objects, failed recipients, events, message restoration and caller identity/configuration. Metadata controls cover nested/invalid/absent status, marker precedence, broken getter refusal, HTTP 500/transient delivery and stale-status reset.
- Final focused additions pass **1,935 tests / 28,249 assertions** (including existing Graph OAuth/SDK, Gmail and HTTP-guard controls). A wider Graph/Gmail/shared-policy run passed **1,961 / 27,505** before the final extra controls; full suites below include every final case.
- **28/28 focused manual mutations** detected by assertion failures, without bootstrap errors: unsafe boundary/message/cause, terminal markers/Error chains, Kiota/Guzzle/nested/numeric status, redirect priority/range, HTTP 500, faulty metadata inspection, sensitive error/bound-callable inputs, OAuth status/terminal handoff, synchronous/asynchronous rejected redirects and per-request/explicit reset. Original snapshots restored per run/final cleanup. This is not an Infection MSI score.
- A late authentication control reproduced the shared-classifier gap for standard OAuth `400 invalid_client`: 16 metadata cases had 13 assertion failures before the safe typed error-code signal was added. ### Review Notes

Targets !34 (`b86ba553`), retaining its prerequisite stack. No GitLab MR was merged. Ordinary errors retain their ordinary Swift class, while redirect/Error failures remain terminal even after unsafe causes are discarded. Recognized RFC 6749 OAuth error codes at status 0/400 receive a static authentication-failure signal so default retry does not replay invalid client/grant/scope requests; transient OAuth codes and authoritative server statuses remain retryable. Correcting 401/403/501 codes changes prior accidental connection-style retries. Other shared retry/failover rules remain unchanged. The OAuth internal carrier retains a cause only until the outer send detaches it; arbitrary caller frames, callbacks and SDK logging remain caller-controlled. Review state reset across retries/CAE carefully. #86 and the remaining #30 work stay open.
