## Design

### Approach
Use `fix/55-isolate-gmail-sdk-requests` based on !17 (`78a74334`). Keep Gmail's real SDK request construction, authentication, retry runner and response decoding, but execute through a transport-local SDK copy and a scoped Guzzle-compatible redirect guard. Preserve caller-owned SDK/HTTP configuration and handler stack; share the SDK token cache so authentication behavior persists across sends. Also fix the confirmed deferred-request false-success mode (#56).

### Changes
- A small ClientInterface decorator forces per-request redirect refusal, rejects 3xx responses with the existing non-retryable marker and exposes a cloned handler configuration to SDK authentication (which creates its own Guzzle clients). Place request policy before redirect middleware and response validation before SDK retry decoding. Delegate ordinary errors and async behavior normally.
- Gmail send creates a scoped copy of the supplied standard Google Client, uses the shared cache and guarded HTTP client, and forces immediate execution on the copy. Caller defer/client/defaults/handler stack remain unchanged. Fail clearly for non-cloneable or non-cooperating SDK customizations; reject any returned deferred request instead of counting it as sent.
- Preserve the existing zero-return behavior for ordinary SDK exceptions while letting the non-retryable marker propagate through the SDK send-event cleanup path.
- Real SDK/auth/redirect tests cover redirect statuses/destinations, fresh/expired credentials, token-cache/callback behavior, retry settings, successful and error decoding, caller state, deferred mode, MIME/attachments, explicit envelope policies and failure cleanup. All fixtures use fabricated credentials.
- Register the new helper in metadata/runtime aliases without importing the independent #51 generator change. Update release/API/security documentation and shared docs/issues/55.md.
- Assess SES and Graph SDK boundaries independently with installed-source review and no-provider probes; record concrete separate findings instead of claiming blanket SDK protection.

### Acceptance Criteria
- Failing-before/fixed-after public-send evidence for Gmail redirects and deferred false success, using real middleware and no real provider email/tokens.
- One Gmail request on a redirect and no automatic replay, including default Swift retries and SDK retry configuration. A separate necessary token exchange may occur; token-exchange redirects must also fail closed.
- Caller SDK HTTP client identity, defer mode, client options and handler stack stay intact; SDK callbacks and shared token cache retain ordinary behavior across sends.
- Normal SDK success/error decoding, MIME/Bcc/attachment fidelity, policy/envelope cleanup and existing count behavior remain covered. No direct-HTTP regressions from !17.
- Helper sync/async paths and SDK-created client configurations are tested. Unsupported SDK customization fails before sending rather than bypassing the guard.
- Full PHP 8.3/8.5 suites, PHPStan, full style, strict Composer validation and final-head required CI pass. No baseline/profile/threshold changes or merge.

### Risks
SDK cloning is required for isolated configuration; the standard Google Client supports it. User subclasses must honor SDK cloning and HTTP configuration setters. Authentication uses the same cache/credential objects and callbacks, but request configuration is isolated. The SDK's own middleware/client creation must retain the policy, so simple outer wrappers alone are insufficient. Other SDK transports have distinct interfaces and ownership boundaries. The unmerged API stack and optional CI prerequisites #38/#40/#45/#46 remain pending review/integration.
