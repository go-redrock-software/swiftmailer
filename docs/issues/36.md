## Implementation Plan

## Implementation

### Changes
- Suppress Bcc during explicit-envelope SMTP transactions and restore it in a finally block; absent Bcc fields stay absent.
- Correct getBcc() PHPDoc to include its actual null result when the header is absent, so static analysis models the guard correctly.
- Replace the old test that required unsafe Bcc transmission. Add streaming-failure restoration, absent-header and real-message serialization coverage across the inherited SMTP suites.
- Update CHANGES and the sending/security guides.
- Include the two whitespace-only CI corrections tracked in #35.

### Validation
- Before the fix: focused ESMTP regressions produced two Mockery ordering errors, proving transmission occurred without the required Bcc suppression/restoration.
- A local SMTP recording server captured the Bcc header before the fix. Afterward, DATA contains no Bcc header while RCPT TO still includes both explicit recipients. No external mail was sent.
- PHP 8.5.11: composer test exited 0; 4,197 tests, 24,848 assertions, 30 skipped. Existing dependency deprecations remain.
- PHP 8.3.35: project PHPUnit exited 0; 4,197 tests, 24,838 assertions, 30 skipped, two existing PHPUnit API warnings. Used the standard deprecation baseline; the cached bridge runner requires PHP 8.4.
- Full PHPStan analysis passes after correcting the getter documentation. Full formatter dry run and git diff --check pass.

### Review Notes
The explicit MAIL FROM/RCPT TO values are unchanged. Bcc is removed only during the transaction and restored before sendPerformed or exception propagation. This covers SMTP-derived transports; provider-specific raw MIME handling requires separate auditing. The recipient-policy bypass tracked in confidential #37 is not fixed here.
