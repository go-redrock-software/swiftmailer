## Design

## Implementation Plan

### Approach
Make the registered microsoft-graph DSN construct real GraphServiceClient/GraphRequestAdapter instances using explicit authentication, with no constructor I/O or ambient credential discovery. Support fixed externally managed bearer tokens and renewable application client credentials. Reuse the native operation/HTTP/OAuth/acceptance/privacy boundaries from !36 and its prerequisites; keep #30 open for remaining credential/options contracts.

### DSN contract
- Bearer: `microsoft-graph://TOKEN@default`, optionally `?user_id=MAILBOX`; absent mailbox selects delegated /me.
- Application: `microsoft-graph://CLIENT_ID:CLIENT_SECRET@default?tenant_id=TENANT&user_id=MAILBOX`; tenant and mailbox are required and the only scope is `https://graph.microsoft.com/.default`.
- The endpoint host must be default with no port, base path (except /), or fragment. Require nonempty credential values, valid bearer syntax and safe scalar identifiers. Preserve literal-zero and percent-decoded credentials. Canonical single scalar option names only: tenant_id, user_id, retries, retry_delay. Reject duplicates, arrays, PHP-normalized names, foreign provider options and custom resource/token/scope/cloud endpoints. Bearer mode cannot silently ignore a password or tenant.
- Append optional caller-owned Guzzle clients for Graph resources and token exchange after existing SES/Gmail constructor arguments. Keep them separate; construction must not send or mutate either client's configuration/handler stack. The Graph resource and token endpoints are fixed global HTTPS endpoints; upload URLs receive no factory-added bearer credentials for unrelated hosts.

### Changes
Add a small SDK-compatible static bearer authentication provider and a narrow ClientCredentialContext compatibility adapter for literal-zero fields if probes confirm the native truthiness limitation. Keep native League/Kiota token parsing, grants, cache, renewal and CAE for application authentication. Construct explicit Graph authentication/adapter/service clients with fixed scopes/base URL, without setting bearer defaults on the HTTP client. Extend scheme-scoped parsing and source-safe constructor failures. Update provider/DSN/Graph/security docs and #30's audit map.

### Acceptance Criteria
Failing-before real SDK construction/wire fixtures cover bearer, application, zero/encoded fields and invalid inputs. Assert real adapter/provider/client ownership before sending; no fake SDK or bypass hook may prove successful delivery. Verify /me and /users mailbox URLs, token endpoint/form/scope, cache and later renewal/CAE, typed SDK serialization and valid send/draft/upload/calendar completion. Prove constructor no-I/O, safe diagnostics/printed exception graphs with argument recording on/off, and no transfer of bearer/client secrets through resource/token redirects or foreign upload hosts. Exercise policies/envelopes/events/restoration, retry/pools and hard acceptance failures through DSN-created transports. Update old fixtures that deliberately expect unsupported Graph DSNs so they remain invalid and cannot attempt live requests. Full PHP 8.3/8.5, PHPStan/style/strict Composer/generated map/aliases, focused manual mutations and exact-final-head required CI pass. Record optional CI outcomes accurately. No dependency/vendor/baseline/threshold changes or GitLab merges.

### Risks and Sources
This makes a formerly registered-but-rejected route operational. A valid bearer DSN must never be used as an invalid CLI/privacy fixture. Fixed tokens cannot renew themselves; callers must supply a fresh token or choose application credentials. Application mode requires real Entra application permissions and an explicit mailbox, while .default reflects the app registration's grants. Kiota's BaseSecretContext rejects string zero and its generic bearer provider uses token truthiness; preserve explicit DSN values without weakening global SDK behavior. Native delegated authorization-code/OBO/certificate, managed credentials, national-cloud and custom scope/client configuration remain available through native construction, with further work tracked under #30. Current Context7 Graph SDK docs, official Graph authentication/Entra client credentials docs and installed Kiota/League source establish the contracts. Base is ready, unmerged !36 (`f45d4710`).

## Implementation

### Changes
- DsnTransportFactory now constructs native GraphServiceClient/GraphRequestAdapter instances for explicit bearer and application client credentials. Existing SES/Gmail constructor argument positions are preserved; Graph resource/token clients are appended separately.
- GraphBearerAuthenticationProvider preserves literal-zero tokens, restricts authentication to the exact Graph HTTPS origin, strips stale authorization and refuses same-token claims replay.
- GraphClientCredentialContext initializes native grant/cache/CAE state while preserving explicit zero tenant/client/secret fields rejected by the SDK parent truthiness checks.
- GraphRequestPolicy recognizes typed unresolved native CAE failures for #88 without inventing HTTP status or a hard marker. Authoritative transient metadata retains precedence.
- Two generated-map/namespace aliases and DSN, provider, Graph, security and #30 audit documentation are updated.

### Approach and compatibility
Construction performs no HTTP I/O or ambient credential lookup. Graph API v1.0, global Entra login, Graph allowed hosts and application .default scope are fixed. Strict canonical scalar options reject duplicates, arrays, normalized aliases and foreign provider configuration. Client secrets permit printable ASCII spaces; identifiers and bearer tokens have narrower validation. Percent-decoded and literal-zero fields reach real wire requests.

Caller resource configuration is copied and its stack cloned. The native SDK URL replacement middleware is installed for /me, and http_errors is false so Kiota can process CAE. Resource auth and Authorization defaults are removed from the private copy; unrelated headers/options and original caller configuration remain intact. The separate token HTTP client is owned by the native OAuth provider and scoped by the existing per-send boundary. Native League/Kiota parsing, grants, cache, expiry, renewal and callback publication are retained. Advanced flows/clouds/managed credentials remain native SDK configuration under #30.

Pre-wire ownership guards prevent mutated bindings from reaching real networking. No fake SDK delivery seam is used.
