## Design

## Implementation Plan

### Approach
Resolve #41 using observable streaming behavior through real PHP-FPM/FastCGI and CLI child processes, retaining the reporter's existing production output and both flush calls. Do not classify the two surviving mutations as universally equivalent and do not weaken mutation thresholds.

### Evidence
A private Unix-socket FastCGI probe on PHP 8.3.35 and 8.5.11 holds each script at an explicit control barrier after notify(). Both PASS and FAIL reports arrive before release with output_buffering=0; removing flush() prevents early delivery. With PHP output_buffering=4096, neither original nor mutated flush drains the user buffer before completion. All owned FPM masters/workers are stopped after the probe. PHP's official flush/output-buffer manual agrees; the PHP 8.4 header-only change does not change this body-output proof.

### Changes
- Add a small source-aware isolated reporter fixture and streaming regression tests. Use a private FPM Unix socket, FastCGI records and a separate ready/release control barrier rather than sleep-based timing or a mocked flush call. Assert early complete escaped output and deferred completion, then final output and process cleanup.
- Preserve the actual reflected source-file mapping before Composer bootstrap in child requests so Infection's flush-removal mutants execute in the FPM worker rather than an original eager namespace alias.
- Cover PASS/FAIL, CLI and FPM, no user buffering and a real PHP user-level output buffer. Make buffering limitations explicit. No browser-rendering, Apache/proxy-buffering or live delivery claim.
- Use official PHP FPM CI images for the unit/mutation runtime while retaining CLI test commands, and require FPM availability/version agreement there so the important tests cannot silently skip. Local environments without FPM receive an explicit skip; no optional opt-out in required CI.
- Update reporter/contributor documentation and docs/issues/41.md. No production reporter behavior change, dependency/vendor/baseline changes, mutation exclusions or threshold reductions.

### Acceptance Criteria
- Actual client bytes distinguish both removed flush calls on PHP 8.3 and 8.5 before releasing the request barrier; final bytes and normal output escaping remain exact.
- Buffered controls demonstrate flush cannot empty PHP user buffers. CLI observations are measured rather than inferred from the passing FPM case.
- Every owned child/FPM process is reaped, including assertion failure and timeout paths. All test I/O stays on private local sockets/temporary paths; no external endpoint or user service is used.
- A focused Infection run executes the actual reflected mutant source in the child, kills the two flush-removal mutants and reports its real score under unchanged minMsi 78 / minCoveredMsi 95. Preserve and inspect all other focused outcomes.
- Focused/full PHP 8.3/8.5, PHPStan, fresh uncached style, strict Composer, generated aliases and exact final-source CI pass. Target develop; prepare a reviewable MR and record issue state accurately.

### Risks
FPM is a separate SAPI and is not shipped by every PHP CLI installation. Tests must find a compatible binary, enforce it in CI, and use short private socket paths with strict cleanup. Windows/no-FPM environments cannot prove the FastCGI guarantee and must say so. PHP/user/web-server/proxy/browser buffering remain distinct; document limits without claiming universal real-time rendering. ## Implementation

### Changes

- `tests/unit/Swift/Plugins/Reporters/HtmlReporterStreamingTest.php`: eight cases covering CLI/FPM, PASS/FAIL and PHP user buffering. Each compares captured HTML with client bytes across an explicit completion barrier.
- `tests/fixtures/html-reporter-stream.php`: isolated worker loading the selected reporter implementation before Composer's eager aliases.
- `.gitlab-ci.yml`: matching official FPM images and mandatory FPM availability for unit/mutation jobs. CLI test commands and existing mutation configuration remain unchanged.
- `doc/plugins.md` and `CONTRIBUTING.md`: measured behavior, buffering limits, runtime requirements and source-mapping details.
- Production reporter, dependencies, vendor files, baselines, thresholds and excluded mutators are unchanged.

### Approach

The FastCGI client reads actual response records while a separate private socket holds the worker after `notify()`. An unbuffered report must already be complete; buffered controls must still be empty. Releasing the barrier must produce identical final HTML, no FastCGI error output and a successful end-request record. CLI cases measure the same boundaries without treating already-unbuffered CLI output as proof of backend flushing.

Infection 0.29's include interceptor preserves the original Reflection filename even when loading mutant bytes. The harness checks its active replacement mapping and passes the actual physical mutant to the worker, then verifies the worker's reflected filename. This version-specific boundary deliberately fails if its expected properties disappear. Every case also calls the reporter in the parent to assert captured/streamed HTML parity and provide actual source-line coverage. All subprocess descriptors use pipes to avoid re-entering Infection's file wrapper through process descriptors.

Workers use private temporary paths, a private FPM pool and Unix sockets. Only controlled configuration and `XDEBUG_MODE=off` reach child environments. Bounded startup/request/termination windows and `finally` cleanup release the barrier and reap owned processes on both success and assertion failure.

### Validation

- Independent FastCGI proof: 16 cases across PHP 8.3.35/8.5.11, configured output buffering 0/4096, original/removed flush and PASS/FAIL. With buffering disabled, each removed flush prevents early delivery on both versions; configured user buffering delays both original and mutant output. Final output remains present. All owned FPM processes were reaped.
- Before focused native Infection audit: 24 existing reporter tests / 44 assertions; 12 mutants generated, 10 killed and the two flush removals escaped; covered MSI 83.33%, exit 1 under the unchanged 95% covered threshold.
- After focused native audit: 32 reporter tests / 300 assertions; all 12 mutants killed, covered MSI 100%, exit 0. Zero escaped, ignored, uncovered, errored, syntax-error or timed-out mutants. Detailed killed-mutant logs confirm the PASS and FAIL flush removals fail the corresponding unbuffered FPM early-body assertion with an empty actual body, rather than a harness/framework error.
- The native audit uses PHP 8.5/Xdebug and precomputed PHPUnit coverage. The installed Symfony bridge emits a PHP 8.5 startup deprecation before its handler; Infection's initial runner treats stderr as an early failure. Running coverage directly and using the repository's `--skip-initial-tests --coverage` workflow avoids that runner limitation without suppressing deprecations or changing dependencies. PHP 8.3 has the independent real-FPM behavior proof; no native PHP 8.3 mutation score is claimed.
- Full suites with `SWIFTMAILER_REQUIRE_FPM=1`: PHP 8.3: 11,439 tests / 114,120 assertions; PHP 8.5: 11,439 / 114,136. Both exit 0 with the same 30 existing skips; PHP 8.3 retains its two pre-existing PHPUnit E_ERROR-expectation warnings. No owned reporter workers remained after either run.
- PHPStan: no errors. Strict Composer validation: valid. All 242 generated map entries match source declarations and runtime aliases. GitLab CI lint: valid, no errors/warnings. Fresh style checks, including both new PHP files explicitly: clean.
- Final-source CI is recorded in the MR checks and validation comment after the last push; only results matching the current source SHA count. The MR mutation-diff job may skip because no production PHP source changes; that is separate from the real focused local audit above.

To reproduce the focused native audit with PHP 8.5 and Xdebug, run the following from the worktree. Use `HtmlReporterTest` and a different coverage directory for the before control; use `HtmlReporter` for the expanded suite. Run them sequentially and do not edit PHP source/tests while either is live.

```sh
export SWIFTMAILER_REQUIRE_FPM=1
export XDEBUG_MODE=coverage
export SYMFONY_DEPRECATIONS_HELPER='max[direct]=0&baselineFile=./tests/deprecation-baseline.json'

  --coverage-xml=/tmp/swiftmailer-41-coverage/coverage-xml \
  --log-junit=/tmp/swiftmailer-41-coverage/junit.xml
php -d memory_limit=1G vendor/bin/infection \
  --filter=lib/classes/Swift/Plugins/Reporters/HtmlReporter.php \
  --test-framework-options=--filter=HtmlReporter --threads=2 \
  --skip-initial-tests --coverage=/tmp/swiftmailer-41-coverage \
  --log-verbosity=all --debug --show-mutations --no-progress
```
