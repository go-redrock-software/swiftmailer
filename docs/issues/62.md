## Design

## Implementation Plan

### Approach
Use League's public grant-factory/AbstractGrant extension points on the operation-local OAuth copy created by #60. Keep native token acquisition, signing, cache handling and callbacks. At authentication start capture the context used to calculate native grant inputs; after a CAE callback changes it, rebuild grant-owned parameters from the returned context, remove stale fields, retain SDK scopes and native claims/capability merging, and delegate validation/preparation to the registered grant. Normalize the known certificate refresh assertion-type spelling (#65) without altering JWT bytes.

### Changes
- Add an operation-owned grant policy, delegated factory and grant adapter. Clone factory ownership; keep caller factories/registrations unchanged. Handle ordinary refresh and repeated callback/context transitions, including registered on-behalf-of grants.
- Keep token/authorization endpoints consistent with a returned tenant for checked GenericProvider endpoint fields. Preserve configured origin, national-cloud/custom prefix and query. Reject unsupported endpoint shapes or unsafe tenant changes before a request rather than guessing how to rewrite opaque providers.
- Add an optional pre-dispatch request validator to the existing scoped Guzzle client, used only by Graph OAuth. Validate active fallback parameters and endpoint coherence before caller HTTP/retry middleware can dispatch credentials, including cooperative custom providers. Preserve form/JSON/query and HTTP Basic credential conventions where supported; fail permanently when a changed-context request cannot be verified.
- Publish context and any endpoint changes together with compare-and-set checks so newer caller/reentrant configuration is preserved. Retain source object/HTTP identities and normal shared cache updates. Keep policy failures latched through SDK error handling; avoid publishing unsupported context/endpoint state.
- Document compatibility limits, update Graph handoff, and cover the independent certificate-refresh correction under #65.

### Acceptance Criteria
- Failing-before public Graph send tests inspect actual token URL and code/client/redirect URI/grant/assertion fields after failed CAE refresh and a callback. Cover same/new tenants, scopes/claims, PKCE context parameters, certificate/secret changes, registered grants, cache reuse and repeated challenges in multi-request sends.
- Ordinary expired-cache and CAE certificate refresh use the canonical client_assertion_type while preserving JWT/refresh-token bytes and native behavior outside the defect.
- Exercise configured/national-cloud endpoints, unsupported/opaque cases, caller option/identity preservation, reentrant state, normal errors and existing message/envelope/policy/events. Redirects and unsupported transitions remain permanent without replay or forwarding; source context/endpoints stay coherent.
- No shipped vendor/dependency/baseline/threshold changes. Full PHP 8.3/8.5 suites, PHPStan, style, Composer/diff checks and six required CI jobs at the exact final MR head. Base on !20 independently of !21/!22. No merge is authorized.

### Risks
The SDK calculates grant inputs before callbacks and can discard exception causes. Parameter repair, endpoint coherence and publication must be verified together, not just getter state. Private GenericProvider endpoint fields and SDK claims merging are checked compatibility boundaries. Arbitrary custom provider/grant implementations may not honor their configured collaborators; pre-dispatch validation must reject an unverifiable changed-context request without sending it. Certificate, PKCE and repeated/reentrant transitions need real serialized-request coverage.

## Implementation

### Changes

- Added `GraphOAuthGrantPolicy`, `GraphOAuthGrantFactory` and `GraphOAuthGrant`, with class-map and namespace aliases. The scoped League factory delegates to a private copy of the registered factory, and the grant wrapper retains native preparation/validation.
- `GraphOAuthPolicy` captures authentication inputs, installs the grant and HTTP policies, and publishes compatible context/endpoint state together. It reasserts permanent failures after SDK promise handling.
- `NoRedirectClient` accepts a production pre-dispatch validator around the caller middleware stack. The inner check catches changed requests before the network handler; existing SDK redirect latching remains in force.
- Added 70 public-send/native-SDK regressions in `GraphOAuthGrantPolicyTest` and documented the compatibility boundary in `doc/microsoft-graph.md`.

### Approach

Native Kiota computes parameters before the CAE callback. The new grant adapter rebuilds only the changed-context fallback inputs, removing old credential and grant fields and retaining current scopes and native CP1 claims merging. It delegates to the actual registered grant, including on-behalf-of. Certificate refresh corrects only the known assertion-type spelling (#65); JWT bytes and native signing/cache/callback behavior stay intact.

For tenant transitions, checked GenericProvider endpoint fields are updated on the operation copy while preserving origin, prefix and query. Unsupported tenant or endpoint layouts fail before dispatch. A compare-and-set publication checks source context, provider ownership and both endpoint values before advancing them together. Successful reentrant sends preserve their newer state.

### Validation

- Initial 14 regressions failed before implementation (10 failures, four errors) and passed after it. Expanded coverage: **70 tests, 580 assertions**, passing with real Graph/Kiota/League serialization and synthetic HTTP endpoints.
- Covers code/client-credentials/registered on-behalf-of transitions, same/new tenants, HTTP Basic, native PKCE defaults and context verifiers, claims/scopes, secret/certificate changes, ordinary expired-cache and CAE certificate refresh, native OAuth failures, cache reuse, repeated challenges across draft/upload steps, reentrant sends, national/custom endpoints, cooperative/bypassing custom providers and middleware changes.
- A focused mutation restoring case-sensitive Basic-scheme handling is caught by both stale-credential regressions (two failures before restoration). Valid lowercase Basic authentication succeeds; stale lowercase/mixed-case Basic credentials are rejected before dispatch and publication.
- All five redirect statuses with caller retry middleware remain terminal without forwarding, replay or publishing rejected context. Duplicate/conflicting parameters, malformed Basic credentials and nonseekable fallback bodies stop before HTTP. Successful recipient policies, implicit/explicit envelopes, message restoration and send events are covered.
- The production policy also passed eight isolated bare-authentication probes: same/new tenant, client-credentials and registered on-behalf-of transitions on Kiota 1.5.2 and 2.2.1, each with the supported Guzzle 7 line. They verify current wire parameters/endpoint, coherent context/endpoint publication and unchanged original HTTP/factory identities. The 2.2.1 fixture initially resolved Guzzle 8 outside this project’s constraint; the temporary fixture was pinned to Guzzle 7 before these checks. No project dependency changes.
- Generated class map agrees exactly: **230 entries**. PHPStan, style (521 files), strict Composer validation and diff checks pass. **Full suites: 7,753 tests on each runtime**; PHP 8.5: 73,166 assertions, 30 skips; PHP 8.3: 73,163 assertions, the two existing PHPUnit E_ERROR warnings and 30 skips. Exact-head CI is recorded below when complete.

### Review Notes

The private SDK claims method and GenericProvider endpoint fields are checked compatibility boundaries. Unknown authentication/access-token provider chains keep their own policy. Custom League providers must honor scoped HTTP/factory collaborators and expose verifiable changed-context requests. This does not establish compatibility of the full Graph 2.x stack with Kiota authentication 2.x: the isolated upstream 2.2.1 probes documented on #62/#65 establish the upstream defects, not a supported dependency upgrade.
