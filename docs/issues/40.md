## Implementation Plan

Use the existing isolated Symfony bridge runner (simple-phpunit) for both coverage generation and Infection's custom executable. This delays project Composer autoloading until the mutation bootstrap has installed Infection's include interceptor. Change Composer infection:coverage, Infection phpUnit.customPath, and both GitLab mutation coverage commands together. Keep thresholds, production autoloaders and aliases unchanged. Stack on MR !1 to validate the HTML escaping regressions against real mutants. Reproduce the old all-escaped result locally, then verify that the new runner kills the corresponding mutations and assess any genuine surviving/equivalent mutations.

### Validation
- Before PHPUnit's test bootstrap, class_exists(HtmlReporter, false) is true with the project runner and false with the isolated bridge runner. Both startup probes pass the same real reporter test.
- Old coverage + old runner: 12 covered HtmlReporter mutants, zero killed, 0% covered MSI.
- New coverage + new runner: 12 covered mutants, ten killed, two surviving flush() removals, zero mutation execution/syntax errors, 83% covered MSI.
- The focused run still exits 1 because the unchanged covered-MSI threshold is 95%; the remaining output-flushing coverage gap is tracked in #41. This result is not reported as a passing mutation score.
- New coverage generation via composer infection:coverage succeeds: 3,975 unit tests, 21,893 assertions; PHPUnit XML and JUnit reports generated.
- Full PHP formatting dry run passes across 499 files. composer validate --strict --no-check-publish passes. GitLab's project CI lint API reports valid=true with no errors or warnings. git diff --check passes.
