## Design

### Approach
Use an isolated branch from current `master` (`9200d453`), independently of !14. Make the existing `php generate_class_map.php` command generate both `class_map.php` and `lib/class_aliases.php` from one sorted map of global `Swift_` declarations. Restore the six verified missing runtime aliases and metadata entries.

### Changes
- Keep source parsing separate from rendering/writing so temporary fixture trees can exercise generation without editing the repository.
- Use PHP-Parser's class-like declarations and resolved names; include named global classes/interfaces/traits/enums, skip anonymous and namespaced/non-Swift declarations.
- Sort deterministically, reject conflicting duplicate declarations and propagate syntax/read/write failures; parsing must finish before either generated output is replaced. No silent partial source scan.
- Emit the repository's existing PHP/alias formatting directly so a repeated generation or style pass leaves both files unchanged.
- Add fixture-based generation and normal-autoload alias identity tests; check source-to-map-to-runtime coverage without creating SDK clients or sending email.
- Correct contributor/architecture documentation and add release notes plus `docs/issues/51.md`.

### Acceptance Criteria
- All six reproduced missing aliases work through Composer autoloading and preserve native class/interface identity.
- One command updates both files; repeat generation is byte-identical on PHP 8.3/8.5 and clean after the configured style pass.
- Representative fixture cases cover named symbol kinds, namespaces, anonymous classes, multiple/nested source files, ignored non-PHP input, duplicate names and invalid syntax. Parse errors do not overwrite existing outputs.
- Existing aliases/global names remain available; no production constructors or network calls are needed to verify this.
- Focused/full PHP 8.3/8.5 tests, PHPStan, full style, strict Composer validation and all required final-head CI pass. No baseline or mutation threshold changes.

### Risks
New eager aliases load six additional definitions; verify those definitions introduce no constructor/network work at load time. The generator is development tooling using existing PHP-Parser dependencies; runtime consumers keep the committed alias file. Per-file writes can fail due to filesystem errors; report failure rather than claiming successful synchronized output. Review and merge remain separate; no merge is performed.

## Implementation

### Changes
- `generate_class_map.php`: one sorted map drives both formatted outputs; named class/interface/trait/enum collection uses resolved global names, skips anonymous/namespaced declarations and rejects case-insensitive duplicate symbols. All source parsing completes before output writes. CLI errors exit nonzero; including the tool has no generation side effects.
- `class_map.php` / `lib/class_aliases.php`: eight source symbols restored. In addition to the six reported gaps, the audit found `Swift_SendResult` and `Swift_ReportResult` enums omitted by the old visitor. All 217 previous aliases are preserved; both files now contain 225 entries.
- `ClassMapGeneratorTest`: 19 focused cases check source/metadata/runtime identity, all eight regressions, enum case values/identity, fixture-generated classes/interfaces/traits/enums, namespaces/anonymous declarations, nested/overlapping input trees, ignored non-PHP files, deterministic regeneration, empty input, duplicate/parse failures, CLI status, include safety and write failures.
- `phpstan.neon.dist`: includes the generator in normal CI analysis. The inherited `enterNode(): void` mismatch is corrected to the visitor's nullable-node return contract.
- Contributor/architecture docs and release notes describe the real generation command and runtime/development distinction.
- Two pre-existing style violations on master corrected with whitespace only: Sweego payload alignment and one Google transport test concatenation.

### Validation
