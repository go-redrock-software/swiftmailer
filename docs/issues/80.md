## Implementation Plan

### Verified Problem
Real AsyncAws coerces a malformed successful `{MessageId: []}` response into the string "Array" (with a warning), and both Swift SES transports report a positive send. Missing IDs return an ordinary zero send. Validate acceptance before that coercion, so unknown acceptance is marked terminal and cannot be retried/fallen through as a transient exception. Integrate with #78/#79, without changing SDK/vendor files.

### Changes and Acceptance
On SES SendEmail POST responses only, validate 2xx JSON before SDK deserialization: require an object with a nonempty string MessageId without whitespace/control characters. Invalid JSON, missing/null/scalar/array IDs and malformed values produce a static NonRetryable failure with the safe HTTP status. Do not validate health/credential/error responses against the send schema. Preserve the literal string "0" by presence rather than truthiness in both native transports. Keep ordinary HTTP error status/retry behavior and default/caller HTTP ownership.

Use real AsyncAws plus synthetic HTTP fixtures for both native and DSN-created transports. Cover valid string/zero IDs and Simple/MIME behavior, malformed 2xx responses, retry/failover/roundrobin permanent gating, health operations and numeric SDK errors. #79's isolated graph tests must also pass without vendor warnings or retained secrets. Full PHP 8.3/8.5, current/older SDK compatibility, quality/map/alias checks and final-head CI remain required. No dependency/vendor/baseline/threshold changes or GitLab merge; #30 remains open.

## Implementation

SendEmail 2xx bodies are validated before SDK coercion. Missing, malformed or interrupted acceptance is permanent; valid string zero IDs remain accepted. The 226-case suite verifies native/DSN paths, retry/pool gates, interface access, refusal latching and reset. Health and credential responses are unaffected.

Shared implementation, dependencies and complete validation: [#78](78.md). Full PHP 8.3/8.5 suites and quality checks pass. Final CI is recorded on GitLab. No GitLab merge.
