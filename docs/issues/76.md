### Evidence and Risks
Installed Nyholm 2.0.1 `InvalidDsnException` stores the raw DSN privately and appends it to its message; internal parser frames also retain raw arguments. The metadata helper copies that message and attaches that cause. The CLI prints a regex-masked DSN before transport construction. Reproduced using synthetic markers only; no provider traffic. Static replacement intentionally removes vendor-specific failure subclasses/messages/causes at Swiftmailer boundaries while retaining global InvalidArgumentException compatibility. Direct calls to Nyholm remain outside this boundary.

## Implementation

### Changes and Approach

- The operational factory catches Nyholm's `InvalidDsnException` family around `parseUrl`, replacing it with a static global `InvalidArgumentException` without the original cause. Metadata `parseFunc` uses the same safe failure contract. Parser SyntaxException, URL-type rejection and disallowed-function errors are covered. Existing sensitive boundary arguments remain required because a new exception still captures its callers' arguments.
- The CLI now prints `DSN:       [redacted]` for every resolved DSN rather than attempting partial userinfo masking. Transport class/progress/message summary, exit codes, environment precedence and argv process-list warnings remain intact.
- Added an isolated exception-report fixture and privacy regressions. Child processes load the reflected factory/configuration implementations before normal aliases, allowing mutation runs to exercise their actual source. They report leak booleans rather than dumping credential-bearing exceptions into parent output. Their full trace/object inspection has no PHPUnit caller graph.
- Updated security/DSN/CLI docs and refreshed the #30 requirement map. Successful parser grammar, metadata and operational transport construction remain unchanged. No dependency/vendor/baseline/threshold changes.
