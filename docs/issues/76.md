## Implementation Plan

### Approach
Repair two verified credential-disclosure paths under the #30 security audit, based on !30. Parser syntax failures expose raw DSNs in Nyholm exception messages/arguments/private data; metadata wrapping also retains that unsafe cause. The CLI preview only masks a password and exposes user/API-key credentials and other DSN fields even when supplied via environment.

### Changes
- At the operational `parseDsnUrl` boundary, catch only Nyholm's `InvalidDsnException` family and throw a static global `InvalidArgumentException` without retaining the original cause. Preserve parser behavior and the successful zero-credential adapter. Apply the same safe failure boundary to metadata `parseFunc`; keep valid metadata/function behavior.
- Replace the CLI's partial regex preview with a fixed `[redacted]` DSN display. Continue showing the transport class and normal progress/from/to/subject output, error exit codes and the existing process-list warning for argv DSNs. No claim that arbitrary caller messages or remote provider errors are sanitized globally.
- Add isolated subprocess regression tests with argument recording enabled. Inspect full exception messages/string traces/printed objects and previous chains outside PHPUnit caller frames. Cover malformed syntax/ports/userinfo, URL-type/function rejection, nested operational retry/pool wrappers, metadata entry points, encoded markers and static exception compatibility. Verify actual CLI stdout/stderr for argv and environment paths using null/invalid transports without external I/O.
- Update security/DSN/CLI docs and the #30 requirement map. Keep SDK/client authentication and other #30 work open. No vendor/dependency or parser grammar changes.

### Acceptance Criteria
Credential-bearing parse failures no longer expose fixture secrets via the returned exception, its trace, printed object or previous cause, with `zend.exception_ignore_args` both enabled and disabled. Existing successful parsing/factory/helper/decorator behavior and non-parser errors remain intact. CLI previews never print DSN fields for supported syntax shapes; malformed parsing output remains safe. Failing-before regressions, focused manual mutations, full PHP 8.3/8.5 suites, PHPStan/style/Composer/map/alias/diff checks and six required exact-final-head CI checks. Record optional CI failures accurately. No baseline additions, thresholds relaxed or merge.

### Evidence and Risks
Installed Nyholm 2.0.1 `InvalidDsnException` stores the raw DSN privately and appends it to its message; internal parser frames also retain raw arguments. The metadata helper copies that message and attaches that cause. The CLI prints a regex-masked DSN before transport construction. Reproduced using synthetic markers only; no provider traffic. Static replacement intentionally removes vendor-specific failure subclasses/messages/causes at Swiftmailer boundaries while retaining global InvalidArgumentException compatibility. Direct calls to Nyholm remain outside this boundary.

Context7 could not resolve a matching Nyholm DSN package (returned PSR-7 packages; no quota error), so use installed code and official 2.0.1 source: https://github.com/Nyholm/dsn/blob/2.0.1/src/Exception/InvalidDsnException.php .
