Sandbox retains host-ID and `inbox_id` forms, requires a positive decimal inbox ID, rejects conflicting IDs and applies canonical scalar/duplicate validation. `region` is exclusive to Mailgun/Scaleway; `inbox_id` is exclusive to sandbox. Reuse configured query separator validation.
- Reject gmail+api, microsoft-graph, amazon+api and amazon+http before credential strings reach SDK constructors. Static credential-safe errors; direct native SDK construction remains supported.
- Add constructor-to-wire regression coverage, missing/invalid/ambiguous options, credentials/zero values, public helper/wrappers, errors/redirect behavior, endpoint guard and trace redaction. Update DSN docs, #30 requirements and handoffs.

## Implementation

### Changes and Approach

- Replaced the generic constructor call for six incompatible HTTP provider routes with explicit mappings for Mailgun, Mailjet, Scaleway, Infobip, Postal and live Mailtrap. Scaleway follows the documented project-user/token-password convention; Mailgun uses key/domain and Mailjet public/private credentials.
- Added scoped, canonical scalar/occurrence validation for `region` and `inbox_id`, reusing PHP-configured query separators. Mailgun selects US/EU; Scaleway accepts its currently documented `fr-par` region. Sandbox inboxes are positive decimal identifiers normalized without integer conversion; conflicting host/query IDs reject. Fixed-endpoint providers reject unused endpoint overrides.
- Added readonly path metadata to `Swift_Dsn`. Custom endpoints preserve host/port/base path, force HTTPS, reject invalid host/port/path/fragment input and apply the existing public-endpoint guard. Infobip/Postal receive authority/path without a duplicate scheme; Mailgun receives a complete HTTPS base URL. This retains the existing guard's DNS behavior, including allowing unresolved public-style hostnames; it does not implement DNS pinning.
- Preserved literal-zero keys by null presence, including generic single-key HTTP routes and password fallback. Kept existing generic providers' ignored-host compatibility. Static errors and sensitive private helper parameters keep rejected configuration out of factory trace arguments.
- Rejected all four SDK-backed DSN routes before credentials reach SDK-object constructor parameters. This also prevents the untyped SES HTTP constructor from accepting an invalid string client. Direct SDK-backed transports are unchanged; client/authentication DSN design stays open under #30.
- Updated DSN/API/sending/architecture docs and the #30 requirement map. No provider request/payload implementation, dependencies, vendor files, baselines or thresholds changed.

### Validation

- Failing-before suite: **108 cases, 82 errors and 23 assertion failures** on the previous factory. Final new suite: **131 tests / 515 assertions**, passing with default query separators and `arg_separator.input=&;`.
- Real Guzzle synthetic handlers verify provider-specific authentication and send endpoints, region/domain/project/inbox fields, encoded and zero credentials, fixed message preservation, event dispatcher wiring, lifecycle ping authentication, redirect policy, public helper and retry/pool wrappers. Three raw-envelope routes verify custom base paths and Bcc-free MIME; four fixed-provider cases retain pre-request envelope rejection. No external HTTP request or email delivery.
- Negative cases cover absent credential components, unsupported SDK schemes and wrappers, endpoint private/loopback addresses, malformed host/port/path/fragment input, unused fixed-provider overrides, invalid region/inbox values, wrong-scheme options, scalar/array/duplicate/normalized-name aliases and credential-safe own factory traces with argument recording enabled.
- **15/15 focused manual mutations detected by assertion failures**, covering region/domain/private-key/project mappings, live Mailtrap mode, zero-key preservation, base path/port, endpoint guard, SDK rejection, duplicate validation, inbox positivity/conflict, sensitive trace parameters and fixed-host rejection. Mutants restored after each run and in a final cleanup. Zero-key and inbox-positive mutants use focused subsets to isolate assertion failures from consequential configuration errors in other cases. This is not an Infection MSI score.
- Full PHP 8.5: **8,444 tests / 77,358 assertions / 30 skips**, exit 0. Full PHP 8.3: **8,444 tests / 77,360 assertions / 30 skips**, exit 0 with two existing PHPUnit E_ERROR warnings. Existing indirect deprecations remain.
- PHPStan, strict Composer validation, **531-file** style check and diff checks pass. Generated class map agrees exactly at **231 entries**; eight relevant namespace aliases resolve. Exact-final-head CI results will be recorded in the MR/issue notes.
