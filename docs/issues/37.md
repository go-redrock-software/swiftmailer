## Design

## Implementation Plan

### Approach
Apply allowlist filtering/catch-all redirection and RedirectingPlugin whitelist/target policy to the current SendEvent envelope as well as message fields. Replace readonly envelopes through setEnvelope(), preserving the sender. With an explicit envelope, decide rejection from the filtered delivery recipients, allowing header/envelope mismatches without falling back to header-derived delivery. Never copy hidden envelope-only addresses into MIME headers.

Each policy composes in listener registration order. Add a shared recipient snapshot to SendEvent so recipient-rewriting plugins restore the state before the first rewrite even though completion callbacks run in registration order. A plugin that never ran beforeSendPerformed must not alter the message during cleanup after another plugin rejects delivery.

### Changes
- Swift_Plugins_AllowlistPlugin, Swift_Plugins_RedirectingPlugin, Swift_Events_SendEvent.
- Unit regressions for filtering, all-blocked rejection, catch-all, whitelist, explicit sender preservation, immutable input envelopes, absent headers, and composition/rejection ordering.
- SMTP command capture and HTTP request-payload integration regressions using an offline recording transport/client.
- Security/plugin documentation, CHANGES and docs/issues/37.md.

### Acceptance Criteria
- Blocked envelope-only recipients cannot bypass either safety plugin.
- Allowed envelope-only recipients can deliver without requiring allowed visible-header recipients.
- Original explicit sender and caller envelope remain unchanged; send recipients reflect each policy in order.
- No blocked envelope-only/Bcc address enters visible metadata.
- Cleanup restores the original message for both plugin registration orders and rejected sends.
- Regression tests fail before the fix and pass afterward; full PHP 8.3/8.5 suites, PHPStan and formatting pass.

### Dependencies and risks
Stack on MR !2's branch because header-recipient filtering/restoration was corrected there. This MR will target that branch until !2 merges. SMTP Bcc suppression itself remains the separate fix in !3. Some provider transports currently build payload recipients from headers despite accepting an envelope; shared HTTP lifecycle coverage will use an envelope-aware recording transport, and header-based provider delivery must remain policy-safe too. No provider API contracts need changing for this issue.
