## Design

### Approach
Base an isolated branch on !13 (`fix/49-encode-sweego-attachments`). Route all 17 HTTP provider parsers through one bounded JSON decoder that accepts objects/lists as arrays and rejects nonempty malformed/scalar responses with transport exceptions. Retain provider-specific empty-body handling and the status/header-only success paths. Validate remote values before typed result construction, counts and error formatting rather than catching every TypeError.

A malformed response after a successful HTTP status can describe a send already accepted by the provider. Reuse the byte-identical `Swift_Transport_NonRetryableException` marker and default-classifier cause-chain check from !9, with namespace mappings, so newly handled ambiguous responses are not automatically replayed. Preserve valid provider errors and body limits. Add missing HTTP-status checks where logical-success-shaped bodies could override an HTTP error; contradictory acceptance/status must not cause automatic replay.

### Changes
- Shared HTTP response decoding/value-formatting/result-boundary validation plus small provider parser/status adaptations.
- Reused non-retryable marker/classifier prerequisite from !9; update generated namespace mappings without importing Graph calendar changes.
- Public-send provider matrix with default/injected dispatchers and policy/envelope cases, retry wrapper probes, body-size/stream failure controls and valid-response fixtures.
- Release notes, API/retry documentation and `docs/issues/50.md` handoff.

### Acceptance Criteria
- Establish failing-before/fixed-after evidence for scalar JSON error responses across the family, including failed-recipient arrays and failed-message/completion events.
- Unexpected scalar/null/malformed/object/list error bodies remain in normal transport failure handling without warnings or success events; preserve useful valid provider diagnostics.
- Valid provider objects/lists and header/empty-body success flows still pass. Explicitly document empty-body compatibility and ambiguous nonempty success-response errors.
- With the default retry wrapper, malformed/contradictory potentially accepted responses produce one HTTP request; intentional programming TypeError remains visible rather than swallowed.
- Preserve recipient policies, effective envelope and cleanup on every error path; bound response reads and avoid including raw response bodies in generic parsing exceptions.
- Focused/full PHP 8.3/8.5 suites, PHPStan, full style, strict Composer validation and all required final-head CI pass. No baseline or mutation threshold changes.

### Risks / Limits
This is a response boundary fix, not a blanket catch of programming errors or a strict redefinition of all provider schemas. Empty bodies retain the provider's existing behavior; valid status-only/header acknowledgements remain supported. Custom retry classifiers remain an explicit caller policy. !9's shared non-retryable pieces are reused exactly for merge compatibility; Graph behavior is not pulled into this branch. Optional inherited CI prerequisites remain #38/#40/#45/#46 until !11 is integrated. Validation uses mocks; no provider email or merge is required.

## Implementation

### Changes
- `AbstractHttpApiTransport`: shared bounded decoder, safe response-text/error-list helpers and a message-ID guard before success events or typed result construction.
- All 17 HTTP provider parsers: shared decoding; safe error formatting and targeted acceptance/container/status checks. SendGrid's public error path now uses its parser too.
- `NonRetryableException` and `DefaultRetryClassifier`: byte-identical prerequisites from !9; new marker available through native and namespaced autoloading. No Graph calendar implementation imported.
- `HttpResponseBoundaryTest`: 836 public-send cases; SendGrid's existing parser fixture now declares HTTP 200 rather than relying on mock status 0.
- Changelog and API/retry guides document compatibility and replay behavior.

### Approach
Remote JSON is validated at consumption points instead of catching all `TypeError`s. HTTP errors report failed recipients, dispatch failure/completion and restore effective recipient policies/envelopes. Nonempty malformed or unreadable successful responses, invalid consumed success containers/IDs and recognized contradictory acceptance signals carry the non-retryable marker. Default retry classification checks the entire cause chain before transient-message/code rules.

Empty acknowledgements retain provider-specific behavior. MailerSend 202 and SendGrid status/header-only success paths still ignore their bodies. Valid provider diagnostics and nullable/numeric message IDs remain supported. The existing 1 MB reader limit is preserved; generic parse errors do not echo raw bodies.
