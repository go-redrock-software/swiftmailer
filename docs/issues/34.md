## Design

## Implementation Plan

### Approach
Filter original To, Cc and Bcc independently, preserving allowed addresses, display names and original fields. Determine whether anything was blocked by comparing each field with its filtered counterpart, avoiding merged-address deduplication. Add the configured catch-all to To once if any field lost recipients, preserving its existing To display name. Keep original recipient storage/restoration and omit metadata headers.

### Changes
- Swift_Plugins_AllowlistPlugin::applyRedirect().
- Data-driven regression cases for every field, Cc/Bcc-only messages, overlapping addresses, catch-all deduplication and exact restoration.
- Update redirect-mode documentation and CHANGES.

### Acceptance Criteria
- Allowed To/Cc/Bcc recipients remain in their original fields, with display names preserved.
- Blocked recipients in any field trigger one catch-all To entry, including when To is absent.
- Original blocked Bcc addresses do not appear in serialized message headers; no X-Original-To metadata.
- Every recipient field is restored after sendPerformed, and subsequent sends do not inherit a catch-all.
- Regression tests fail before the fix and pass afterward; full tests and quality checks pass.

### Risks
The plugin guide currently documents the faulty Cc/Bcc clearing. The corrected behavior intentionally delivers to configured allowed Cc/Bcc recipients. Catch-all delivery is explicitly enabled by the application, and blocked recipient details must remain private.

## Implementation

### Changes
- Independently filter all three recipient fields and detect blocked recipients without merging/deduplicating cross-field addresses.
- Add one catch-all To entry only when needed, preserving an existing display name.
- Preserve allowed Cc/Bcc recipients and avoid creating absent Cc/Bcc fields.
- Restore originally absent recipient headers by removing them, including To on Cc/Bcc-only messages.
- Add 10 regression scenarios, each exercised over two consecutive sends, with exact recipient restoration and blocked-recipient privacy checks.
- Update the plugin guide and CHANGES.

### Review Notes
Allowed Cc/Bcc recipients now receive the message in catch-all mode, matching the plugin contract. Catch-all configuration explicitly permits that additional recipient even when it is outside the allowlist. Original blocked Bcc addresses never enter visible headers or metadata. External-service tests remain skipped without service configuration.

Explicit SMTP envelope handling is outside this issue: this change concerns message recipients only.
