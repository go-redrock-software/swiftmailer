## Design

## Implementation Plan

### Approach
Scope each public SES send/health operation to a cloned, configured AsyncAws SesClient. Replace only the copy's HTTP and credential-provider ownership fields; preserve the caller's SDK/HTTP configuration and the original connection identity used by Swift events. Require initialized, cloneable standard SDK ownership; unsupported opaque injected SDKs/providers/decorators fail before a request rather than silently bypassing the policy.

### Changes
- A Symfony HttpClientInterface adapter forces max_redirects=0 while preserving lazy responses and streamed response identity. A response wrapper records a stable 3xx for AsyncAws cleanup/debug bookkeeping; the operation boundary rethrows the permanent policy latch. Clone known Symfony decorator chains and guard each RetryableHttpClient strategy: 3xx cannot reach caller retry decisions; other statuses and delay calculations retain the original strategy. Share an operation failure latch across derived clients and credential requests so SDK fallback cannot hide a refusal.
- Clone the supported AsyncAws credential chain/cache/provider graph, including metadata, container, web identity and INI/role/SSO HTTP ownership. Keep PSR cache objects and immutable credential/configuration objects; publish ordinary in-memory cache and winning-provider changes back with compare-and-set protection, translating scoped providers back to caller providers. Never publish a redirect failure as a credential cache result. Explicitly document the custom-provider boundary.
- Protect both SES transports, actual SDK health operations (false if an older supported package has no probe API), native signing and retries. Check the legacy Http transport's listIdentities health call against the installed SES v2 SDK and track any confirmed companion defect.
- Use a conditionally instantiated anonymous Symfony retry strategy so older supported Symfony releases without retry interfaces still load. Add the minimal anonymous-class guard needed by the existing class-map generator; do not import the unrelated #51 rewrite.

### Acceptance Criteria
- Failing-before public-send coverage for both transports, 3xx statuses and destinations, caller 3xx retries, RetryTransport, credentials and health; assert one initial request, no redirected request, no accepted recipients, a permanent failure, and unchanged caller defaults.
- Real SDK/HTTP fixtures preserve request schemas, AWS signing, raw MIME/attachments/envelopes, message IDs, send/exception events, ping, ordinary retry/error behavior, credential cache reuse/refresh and caller client reuse. Replace affected fake public-send SDKs with real fixtures rather than adding bypass hooks.
- Native loopback HTTP proof for default Symfony clients, using fabricated credentials and ephemeral local servers only.
- Full PHP 8.3 and 8.5 suites, PHPStan, style, Composer validation and diff checks; no dependency, baseline or threshold relaxation. Stack on !20, retain confidentiality and require six successful required CI jobs at the final MR head. No merge is authorized by this plan.

### Risks
Private SDK/decorator fields are checked compatibility boundaries and must fail closed when incompatible. Scoped credential cache publication occurs at operation completion; callbacks retain shared normal caches but cannot depend on identical internal timing. Custom credential providers and HTTP decorators can own arbitrary network behavior and require an explicit supported isolation contract before use. Native Symfony version differences require direct regression coverage.

## Implementation

### Changes
- Added SesRequestPolicy, SesHttpClient, SesHttpResponse and SesCredentialProvider, plus namespace aliases/class-map entries. Both SES sends and available health probes run through checked operation-local ownership.
- Symfony decorator copies guard every retry strategy before caller 3xx retry decisions. Per-request max_redirects=0 stops forwarding. Lazy response wrappers preserve normal status/body/stream behavior and response keys; a refused response exposes a stable status with empty headers/body to AsyncAws so debug logging and repeated SDK destructor resolution cannot erase the operation latch or throw a second unhandled refusal.
- Known credential-provider graphs are copied, including metadata/container, web identity and INI role/SSO HTTP ownership. Leaf-provider guards stop exception-swallowing providers from advancing to fallback credentials. PSR cache keys retain native decorated classes. In-memory credentials/winner updates publish with per-entry compare-and-set, mapping copied providers back to original identities.
- #63 replaces the nonexistent SES v1 health method with the existing suppression probe and resolves its result. Normal success and NotFoundException are healthy; other failures are false. Older SES packages exposing only sendEmail remain usable for sends and return false from ping.
- Replaced fake public-send SES clients with real AsyncAws/Symfony fixtures, preserving payload, policy, MIME-envelope, failed-recipient and event assertions. The class-map generator now skips anonymous classes; regeneration produces the identical 231-entry map.

### Validation
- 689 new regression cases. Initial 84-case suite failed before the fix (80 redirect failures and four option/health errors). The 480 credential-redirect cases also failed against parent 062337ad; the 16 normal credential controls passed there. Updated source passes both matrices and the added controls.
- 31 native HTTP cases use fabricated credentials and ephemeral loopback servers. Both transports stop at the first server for 301/302/303/307/308 with default Symfony HTTP, NativeHttpClient and caller retry middleware. The exact same original SDK subsequently follows its own redirect successfully. Progress callbacks and caller headers remain active; servers are closed in teardown.
- Credential checks cover all metadata stages, container credentials, web identity, INI role assumption, expired refresh, cache/winner reuse, newer caller cache entries, direct/chained PSR cache keys and refusal without saving fallback credentials. Additional checks cover nested retry/trace/scoping decorators, derived defaults, streaming keys, timed SDK resolve, explicit garbage collection, debug logging, cached unsupported ownership and one-shot iterators.
- Full PHP 8.5 composer test: 8,372 tests, 79,495 assertions, 30 existing skips. Full PHP 8.3: 8,372 tests, 79,488 assertions, the two known E_ERROR expectation warnings and 30 existing skips. Existing deprecation policy/baseline remains intact.
- PHPStan clean; full style check clean (526 PHP files); Composer validation and diff checks clean. All four new aliases/maps regenerate identically.
- Isolated compatibility probes passed normal sends and one-request permanent 307 refusal for both transports with SES 1.8.2, Core 1.9.2 and Symfony HTTP 4.4.x-dev/contracts 1.1.13 (no RetryableHttpClient), and with the same SES/Symfony profile using Core 1.30.0. Older-package health returns false. The temporary old-version profile has upstream dependency advisories and is a compatibility fixture, not a release recommendation; project dependencies/vendor/lock files were unchanged. Evidence scripts/logs: /tmp/swiftmailer-59-legacy-probe.php, /tmp/swiftmailer-59-core19-probe.jsonl, /tmp/swiftmailer-59-new-focus.log, /tmp/swiftmailer-59-full83.log and /tmp/swiftmailer-59-full85.log.

### Review Notes
- Stacked on !20 (062337ad); no merge performed. Private AsyncAws and Symfony ownership fields are compatibility boundaries with explicit initialization/type/mutability checks. Only standard SesClient and the documented HTTP/provider implementations are accepted; opaque clients, subclasses, decorators and custom credential providers fail permanently before requests, including warm-cache paths.
- Credential cache publication occurs at operation completion and protects newer caller entries. Arbitrary callbacks cannot depend on identical internal cache-update timing.
- Optional AsyncAws SSO packages are not installed in the regression environment. INI-created STS/SSO clients receive the protected HTTP boundary; SSO package behavior itself has no runtime coverage here.
- Existing ordinary SES sends lose MIME child attachments; confirmed against parent and tracked separately in #64. This MR preserves existing Simple/raw-envelope payload selection and does not claim that attachment issue is fixed.
- The initial synchronous HTTP prototype was replaced with a lazy response wrapper to honor the Symfony contract. Refusals are rethrown at the operation boundary because throwing them directly from SDK status resolution leaves AsyncAws destructor bookkeeping incomplete.
- No production dependency, vendor, baseline or CI-threshold changes. MR CI and terminal optional-job observations are recorded on GitLab for the final head.
