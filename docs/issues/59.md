## Design

## Implementation Plan

### Approach
Scope each public SES send/health operation to a cloned, configured AsyncAws SesClient. Replace only the copy's HTTP and credential-provider ownership fields; preserve the caller's SDK/HTTP configuration and the original connection identity used by Swift events. Require initialized, cloneable SDK ownership and inherited SES operations; unsupported opaque injected SDKs/providers/decorators fail before a request rather than silently bypassing the policy.

### Changes
- A Symfony HttpClientInterface adapter forces max_redirects=0 and validates status before exposing a response to AsyncAws. SES operations already resolve their SDK result synchronously. Clone known Symfony decorator chains and guard each RetryableHttpClient strategy: 3xx cannot reach caller retry decisions; other statuses and delay calculations retain the original strategy. Share an operation failure latch across derived clients and credential requests so SDK fallback cannot hide a refusal.
- Clone the supported AsyncAws credential chain/cache/provider graph, including metadata, container, web identity and INI/role/SSO HTTP ownership. Keep PSR cache objects and immutable credential/configuration objects; publish ordinary in-memory cache and winning-provider changes back with compare-and-set protection, translating scoped providers back to caller providers. Never publish a redirect failure as a credential cache result. Explicitly document the custom-provider boundary.
- Protect both SES transports, actual SDK health operations, native signing and retries. Check the legacy Http transport's listIdentities health call against the installed SES v2 SDK and track any confirmed companion defect.
- Use a conditionally instantiated anonymous Symfony retry strategy so older supported Symfony releases without retry interfaces still load. Add the minimal anonymous-class guard needed by the existing class-map generator; do not import the unrelated #51 rewrite.

### Acceptance Criteria
- Failing-before public-send coverage for both transports, 3xx statuses and destinations, caller 3xx retries, RetryTransport, credentials and health; assert one initial request, no redirected request, no accepted recipients, a permanent failure, and unchanged caller defaults.
- Real SDK/HTTP fixtures preserve request schemas, AWS signing, raw MIME/attachments/envelopes, message IDs, send/exception events, ping, ordinary retry/error behavior, credential cache reuse/refresh and caller client reuse. Replace affected fake public-send SDKs with real fixtures rather than adding bypass hooks.
- Native loopback HTTP proof for default Symfony clients, using fabricated credentials and ephemeral local servers only.
- Full PHP 8.3 and 8.5 suites, PHPStan, style, Composer validation and diff checks; no dependency, baseline or threshold relaxation. Stack on !20, retain confidentiality and require six successful required CI jobs at the final MR head. No merge is authorized by this plan.

### Risks
Private SDK/decorator fields are checked compatibility boundaries and must fail closed when incompatible. Scoped credential cache publication occurs at operation completion; callbacks retain shared normal caches but cannot depend on identical internal timing. Custom credential providers and HTTP decorators can own arbitrary network behavior and require an explicit supported isolation contract before use. Native Symfony version differences require direct regression coverage.
