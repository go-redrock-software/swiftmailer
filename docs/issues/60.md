## Design

### Approach
Use `fix/60-isolate-graph-oauth-requests` based on !19 at `224834e04648f6214dbffaf2be4f9736eff31164`. Extend the operation-local Graph adapter policy to protect the token HTTP client of the standard Kiota BaseBearer/PhpLeague authentication chain. Preserve the original caller objects/configuration and normal cache, refresh, CAE, observability and callback behavior.

Clone the known authentication provider, PhpLeagueAccessTokenProvider and its League OAuth provider without constructors; share the existing token cache/context and related state. Set the copied OAuth provider's HTTP client to NoRedirectClient. Replace only copied ownership fields with checked compatibility access, keeping both BaseBearer and PhpLeague private accessTokenProvider fields consistent. Verify copied getters/setters honor the scoped objects and preserve cache/context identity. Attach the scoped authentication provider to the already scoped adapter. Reject unsupported/non-cloneable known-provider configurations before token traffic. The existing non-retryable marker must survive SDK rejected promises and Swift exception wrapping.

### Changes
- Add a focused Graph OAuth policy helper and native metadata/runtime alias; integrate it at the scoped Guzzle adapter's authentication-provider boundary.
- Reuse the proven HTTP guard for token requests, SDK-created configurations and caller retry middleware. Its latch must stop refresh/CAE fallback attempts from making another request after a redirect.
- Cover standard PhpLeague providers attached through either BaseBearerTokenAuthenticationProvider or PhpLeagueAuthenticationProvider/GraphPhpLeagueAuthenticationProvider. Copy known supported subclasses only when they honor scoped ownership. Keep unrelated/custom AuthenticationProvider or non-PhpLeague AccessTokenProvider implementations unchanged; their internally owned HTTP policy remains their responsibility, documented explicitly. Do not claim control of arbitrary private custom networking.
- Test real default OAuth providers/Graph adapters against in-memory physical handlers, with fabricated client credentials, authorization codes and assertions. Cover initial tokens, expired refresh tokens, fresh cache hits, CAE claims requests, caller retry/default Swift replay prevention, errors, callbacks, normal retries, shared cache reuse across sends, original subsequent caller behavior and unsupported customizations. Compare successful behavior with the native SDK as an oracle.
- #61: preserve Throwable causes in the three Swift exception constructors; keep all legacy causes/messages/codes.
- Keep Graph resource/upload/calendar protection from !19, recipient policies/envelopes/events and original API connection identity. Update release/security/API/Graph documentation and shared handoff.

### Acceptance Criteria
- A redirected standard Graph OAuth request sends exactly one token request, zero resource requests and never reports accepted recipients; credentials/code/assertions are not forwarded. All five redirect statuses and cross-origin, downgrade, relative and loopback targets are covered.
- Refresh/CAE token redirects also fail non-retryably; no fallback or Swift/caller middleware replay. Error text does not expose fixture secrets.
- Successful authentication/cache/refresh/CAE and ordinary SDK errors/retries retain behavior. Existing caller token cache is updated/reused normally across sends; original provider/HTTP identities, defaults/stack and settings remain intact even inside callbacks.
- Non-cloneable or non-cooperating known providers/setters/getters fail before token traffic. Anonymous/custom provider behavior remains compatible and precisely scoped in docs; no all-provider claim.
- Public sends still enforce policies/envelopes and always restore recipients/report completion on failure. No resource/upload/calendar regressions, SDK constructor registry resets, vendor edits or baseline/threshold changes.
- Full PHP 8.3/8.5 suites, PHPStan, full style, strict Composer validation, whitespace checks and exact-final-head required CI pass. Publish a reviewable MR targeting !19; move #60 to in-review without merging.

### Risks
The SDK exposes getters but no complete scoped replacement API; private ownership access is a checked compatibility constraint, as in !19. PhpLeague and BaseBearer declare separate private token-provider fields; tests must check actual wire behavior, not just getters. Cache/context sharing and subclass callbacks require explicit regression controls. Unknown custom providers can own arbitrary clients outside this supported chain and must not be silently represented as protected. SES #59 and optional CI prerequisites #38/#40/#45/#46 remain separate.

## Implementation

### Changes and approach
- Added GraphOAuthPolicy for standard BaseBearer/PhpLeague authentication chains. Clone auth/token/OAuth objects without constructors, share cache/context and preserve callbacks, observability and ordinary provider behavior. Replace copied ownership fields with explicit compatibility checks, including the duplicate private token-provider fields on BaseBearer and PhpLeague.
- Integrate at the already scoped Guzzle adapter authentication field. Unknown/custom authentication and non-PhpLeague token providers retain their own policy; no universal token-client claim. Native metadata/runtime alias added without importing independent #51 generator work.
- Expose NoRedirectClient::assertNoRedirect and reassert the operation latch around authentication completion. The SDK can discard a refresh error during CAE or attempt a fallback grant; the wrapper retains the non-retryable marker and the HTTP latch prevents another wire request.
- Publish normal mutable SDK state (derived scopes and callback-returned context) after authentication, using expected-state checks to preserve newer caller/reentrant updates. Advance the expected state after each publication so repeated challenges within one upload retain the latest context. Original HTTP/provider ownership is never temporarily rewritten.
- Validate token HTTP configuration at scope creation, even on fresh cache hits, so later CAE cannot reach an unsupported client. Validate the legacy dependency's untyped getter at a runtime boundary; no PHPStan ignores, type-certainty relaxation or baseline changes.
- #61: widen previous causes to ?Throwable in Swift_SwiftException, Swift_IoException and Swift_TransportException. The public Graph callback control exposed a second constructor TypeError masking the original callback TypeError. Existing Exception causes remain identical; Error causes now survive through all three constructors and native/namespaced entry points. The default classifier treats an Error anywhere in the cause chain as permanent before transient code/message heuristics, avoiding automatic replay introduced by successful wrapping.

### Evidence and verification
- Before implementation, all 480 initial/refresh/CAE redirect cases failed. After, all 480 passed / 6,840 assertions. Matrix covers five statuses, four targets, three credential contexts, three standard auth attachment forms, caller retry middleware and CAE with/without callback.
- Added native-SDK oracle runs for initial authentication, fresh-cache and expired-refresh reuse across sends, plus a two-challenge CAE callback/context transition during a real SDK upload. The repeated-context control exposed and fixed a publication-state bug before review.
- Added malformed HTTP getter/configuration, unsupported clone/cache/getter/setter, cached-configuration, original caller behavior, callback Error/Exception, normal token 503 retry/400 errors, nested token failure and recipient-policy/envelope controls. The cached-invalid-config test failed before eager validation and passes after.
- Exception causes/classification: 28 tests; before widening, 13 Error/chain cases failed while six legacy Exception controls passed. Native/namespaced cause identity and a retry marker behind TypeError now pass. The public Graph callback TypeError retains its original cause and failure cleanup. Nine nested Error/code/pattern cases plus a public callback replay control failed before the classifier guard; the latter made three token requests. All now pass without replay.
- Final focused OAuth/cause/retry suite: 663 tests / 7,527 assertions, including existing classifier/wrapper tests. This adds 534 OAuth and 28 cause/classification cases to the !19 base.
- Full PHP 8.5 and 8.3: 7,683 tests each / 30 skips; PHP 8.3 retains the two known E_ERROR expectation warnings.
- PHPStan, full style (517 files), strict Composer validation and whitespace checks pass. No baselines, mutation thresholds, vendor edits or dependency changes. Exact-final-head CI is recorded in the MR readiness note.
- All token/resource fixtures are in-memory and use invented credentials, codes and assertions. No provider traffic or email. Existing Graph resource/upload/calendar tests remain in the full suites.

### Review notes
- Private SDK ownership/state access is a checked compatibility boundary. Inspect cloned token/OAuth/provider ownership, public getter/setter cooperation, eager configuration validation, state publication and error-latch ordering. [Official auth/custom-cache examples](https://github.com/microsoftgraph/msgraph-sdk-php/blob/main/docs/authentication_samples.md) were retrieved with Context7; installed SDK source supplies the exact ownership/catch/fallback behavior.
- Original token caches are shared and normal context/scopes updates are published at authentication completion, rather than sharing private PHP property references. This preserves subsequent-send state without changing caller-owned clone/reference semantics. A newer reentrant update is not overwritten.
- SDK callbacks retain ordinary invocation and error behavior, including CAE callbacks on failed refresh. The terminal check outside the SDK prevents a swallowed redirect from becoming retryable. Arbitrary custom-provider networking remains caller-owned and explicitly documented.
- #61 expands accepted cause inputs through three constructor signature changes and keeps PHP Error causes permanent under default retries. Internal response helper signatures are unchanged because their call sites only require Exception causes.
