## Design

## Implementation Plan

### Approach
Override `FailoverTransport::setTransports()` to clear its cached current backend after delegating pool ownership to the parent. Preserve historical last-success state until the next send, constructor signatures, plugin ownership and sticky failover selection within an unchanged pool.

### Acceptance Criteria
- Four failing-before public lifecycle regressions: replace after a successful send, replace before ping, empty then refill, and reentrant pool replacement during a terminal send. Run the same scenarios against round-robin as controls.
- Subsequent requests use only the configured replacement; keep new caller state during terminal cleanup (#66).
- Share #66’s worktree, handoff and MR; pass full PHP 8.3/8.5 and six exact-head required CI jobs. No dependency/baseline changes or merge.

### Evidence
The eight added regressions produce exactly four failures on the current #66 worktree: failover keeps using/pinging the cached old backend; all four round-robin controls pass. A separate real-HTTP probe confirms two old-backend requests and zero replacement requests despite the configured pool containing only the replacement.

## Implementation

`FailoverTransport::setTransports()` now resets the cached current backend after replacing the parent-owned pool. The field’s native nullable type matches its lifecycle. Historical last-used state is preserved until another send starts; unchanged pools keep sticky failover behavior.

Four failing-before regressions cover replacement after success, replacement before ping, an empty pool followed by reconfiguration, and a callback replacing the pool during a terminal send. The same round-robin cases serve as controls. Additional configuration-counter tests preserve replacements during ordinary failure handling and terminal cleanup, including replacements equal to the remaining pool.

See the shared [#66 handoff](66.md) for the 146-test regression suite, focused manual mutation audit and complete validation.
