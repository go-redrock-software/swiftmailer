# Issue #65: Consistent certificate refresh assertion type

**Branch:** fix/62-refresh-graph-cae-grants
**MR:** https://code.go-redrock.com/trac/swiftmailer/-/merge_requests/23
**Issue:** https://code.go-redrock.com/trac/swiftmailer/-/issues/65

## Design

Normalize the known certificate refresh assertion-type spelling through the scoped League grant adapter, preserving JWT bytes, refresh/scopes/claims, cache and redirect policy.

## Implementation

The scoped grant adapter recognizes the native certificate refresh spelling
`urn:ietf:params:Oauth:client-assertion-type:jwt-bearer` and uses the canonical
lowercase `oauth` form. The existing signed JWT, refresh token, scopes, CAE claims
and cache behavior are retained. Pre-dispatch validation and the existing redirect
latch prevent custom request changes or a 3xx response from bypassing the policy.

The real SDK tests cover both expired-cache and CAE refresh, all five redirect
statuses with/without caller retry middleware, and secret/certificate context
transitions. See the shared [#62 handoff](62.md) for implementation and validation.

Upstream Kiota authentication 1.5.2 reproduces the casing defect; the isolated
2.2.1 probe uses the correct spelling. No dependency upgrade is included.
