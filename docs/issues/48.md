## Design

### Approach
Base the isolated branch on !10 (`fix/44-bind-default-api-listeners`), which supplies the explicit-envelope and default-policy lifecycle fixes. Replace Sweego's flattened recipient construction with native `recipients`, `cc` and `bcc` arrays, preserving field roles and optional names. Do not emit public Cc/Bcc headers; retain existing Reply-To behavior. Reject an empty To list before HTTP because the documented API requires at least one public recipient.

### Changes
- `lib/classes/Swift/Transport/Api/SweegoTransport.php`: role-preserving address-object mapping, minimum-To guard, remove flattened Cc/Bcc handling.
- `tests/unit/Swift/Transport/Api/SweegoTransportTest.php`: correct old flattened-payload assertions and add focused regressions through public send, including default dispatchers/policies and explicit envelopes.
- User-facing change note / provider documentation and `docs/issues/48.md` handoff.

### Acceptance Criteria
- Demonstrate the old implementation fails new privacy assertions before changing production code.
- To/Cc/Bcc stay in their own fields, display names including `0` survive, omitted optional roles stay omitted and mixed recipients retain the correct count.
- Cc/Bcc-only (including after policy filtering) fails before HTTP; source message fields restore after policy success/failure. No blind address is promoted to public To.
- Default-constructor allowlist/redirect and accepted/rejected explicit envelopes retain the #39/#44 behavior.
- Focused tests, full PHP 8.3/8.5 suites, PHPStan, full style, strict Composer validation and required GitLab CI pass.

### Risks / Validation Limits
Sweego requires a public To and therefore cannot represent Cc/Bcc-only messages with correct field roles. Document this explicit limitation instead of constructing an invalid/unsafe payload. Attachment encoding/filtering remains #49 and mutation coverage remains #47. This branch does not absorb unrelated !11 CI changes; inherited optional smoke/mutation setup failures remain #38/#45/#46 until those prerequisites are merged. No live email or merge is part of validation.

## Implementation

### Changes

- Sweego transport maps To to the public `recipients` list and Cc/Bcc to native copy-role lists. Empty optional roles are omitted; optional names, including `0`, are preserved.
- Rejects messages with no public To before HTTP, after policy processing and existing envelope validation. Reply-To and total delivery counts are retained.
- Adds 34 public-send privacy cases and corrects old tests that expected flattened recipients. Updates the schema contract for native role fields and the documented minimum To count.
- Adds the security release note and documents the provider limitation in `doc/api-transports.md`.

### Evidence

Primary sources retrieved 2026-10-15: [recipient visibility guide](https://learn.sweego.io/docs/sending/how_to_send_email_by_api) and [send schema](https://learn.sweego.io/docs/sweego/send-send-post). The guide explicitly states the public To semantics of `recipients`; the schema defines native Cc/Bcc lists and minimum one public recipient.

Before production changes, the eight role-mapping probes produce six failures and two passing unnamed-To controls. The failure output includes the blind address in the public array. With the fix, the full suite passes all 34 new cases: named/unnamed/zero names, implicit/matching envelopes, incompatible envelopes rejected before HTTP, Cc/Bcc-only rejection, default-constructor allowlist/catch-all/redirect policies, provider failure cleanup, and redirect supplying a safe public To before validation.

Validation: PHP 8.5 full suite passes 4,466 tests / 27,581 assertions / 30 service skips. PHP 8.3 passes 4,466 tests / 27,580 assertions with two existing PHPUnit E_ERROR expectation warnings and 30 service skips. PHPStan, full formatting (503 files), strict Composer validation and diff checks pass. Required CI remains pending publication.
