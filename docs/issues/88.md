# Issue #88: Unresolved Graph CAE authentication retries

**Branch:** feat/87-construct-graph-sdk-dsns
**MR:** Pending
**Issue:** https://code.go-redrock.com/trac/swiftmailer/-/work_items/88

## Design

A real GraphServiceClient/GraphRequestAdapter/League/Guzzle synthetic fixture returns resource HTTP 401 with a WWW-Authenticate claims challenge after a successful application token response. Without a refresh token or CAE callback, Kiota throws ContinuousAccessEvaluationException coded zero. The detached Swift failure also has code zero and no authentication signal, so the default retry wrapper repeats the resource request three times using the same cached token (one token request). No real credentials/provider request was used.

Evidence: {"code": 0, "terminal": false, "retryable": true, "resources": 3, "tokens": 1, "previous": false}

Discovered while implementing #87 on !36.

## Implementation Plan

### Approach
Recognize the native Kiota ContinuousAccessEvaluationException as a typed authentication failure when safe numeric metadata is zero (or the existing OAuth 400 fallback). Emit only the existing static authentication-failure diagnostic, keeping all SDK causes/claims detached. Preserve real token/resource HTTP status and transient classifications when authoritative metadata exists.

### Changes
Extend the Graph failure adapter's authentication classification using the native exception type. Add failing-before real SDK default-retry and direct metadata controls, plus DSN-created native callback/cache tests and isolated exception-graph privacy. Record the shared implementation under #87, targeting !36.

### Acceptance Criteria
A synthetic resource 401 claims challenge with an application token, no refresh token and no CAE callback yields one resource attempt and one token request through the default Swift retry wrapper. Existing safe code-zero metadata remains zero, classifier treats the static message as authentication failure, no original message/claims/cause is retained, and no hard-failure marker is invented for ordinary authentication refusal. Authoritative transient statuses and valid native callback behavior remain intact. Shared full PHP 8.3/8.5, static/style/Composer/map/alias/mutation and final-head CI checks pass. No vendor/dependency/baseline/threshold changes or GitLab merge.

### Risks
This intentionally stops accidental connection-style retries of an unresolved authentication challenge. It does not implement an interactive callback, invent a resource status for a code-zero exception, or alter the SDK's own token refresh contract. Native SDK construction remains available for advanced CAE callback ownership; #30 stays open.


## Implementation

GraphRequestPolicy now treats the native typed CAE exception as an authentication signal only when safe status is zero or the existing 400 fallback. Its static diagnostic stops connection-style default retries without retaining claims/SDK causes, inventing 401 or adding a hard marker. Authoritative 500/503 metadata keeps precedence.

Real native SDK proof after the change: {"code": 0, "terminal": false, "retryable": false, "resources": 1, "tokens": 1, "previous": false}.

Five typed/nested metadata controls and a real default-retry regression accompany native callback/cache publication and isolated privacy coverage. Shared full validation and 37 manual mutations are documented in [#87](87.md).
