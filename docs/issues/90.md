## Design

User priority: preserve working applications and prevent duplicate delivery. Compare the merged develop tree (`2cb8116d`) against pre-merge master (`9200d453`), reproduce failures before modifying production code, and retain delivery/privacy safeguards. Historical feature requests remain deferred. The user has already authorized finishing, merging into develop, commenting and closing resolved work; no additional merge permission gate applies.

The original timestamp-array proposal was rejected during review: it changed the private serialized pool storage type. The implementation retains SplObjectStorage and copies it before writes. A nullable default permits older serialized pools and constructors that skip the parent; existing stored object values remain compatible. No subclass parent clone hook is required.

## Implementation

### Findings and corrections

| Finding | Impact | Correction |
| --- | --- | --- |
| Shared failure timestamps after shallow pool clone | Recovery in one clone crashes another; failures overwrite independent deadlines | Copy metadata before recording/removing failures; retain caller-owned backend identities and weighted slots |
| Legacy pool subclass skips formerly empty parent constructor | First failed backend accesses an uninitialized typed property | Initialize metadata lazily and preserve legacy startup behavior |
| Recipient snapshot bypasses overridden getMessage() | Plugins restore recipients from an unrelated parent message | Capture the effective message through the public getter |
| Equivalent API envelope repeats addresses across To/Cc/Bcc | Valid send rejected before HTTP | Compare normalized audience sets, keeping local-part case significant and rejecting true overrides |
| Default 60-second pool recovery changes explicit start() | Existing applications cannot immediately revive failed backends | Preserve manual recovery unless a constructor period, setter or DSN option explicitly enables timed recovery |
| Plugin instance owns one shared recipient snapshot | Nested/out-of-order completions lose another message's originals (also observed before the merge train) | Each event owns its snapshot; plugins retain no event/message history |
| Caller Gmail/SES middleware retries successful send responses | Two wire sends for one logical message (also reproduced against the pre-merge baseline); strategy exceptions after acceptance permit outer retry | Gmail validates every wire attempt; SES records successful send headers before caller retry decisions and refuses replay |

All public/protected pre-merge methods, parameter names, defaults, visibility and return declarations were inventoried with PHP-Parser. Existing constructor changes add optional pool periods; exception previous causes widen Exception to Throwable. No removed existing methods/classes or narrowed existing signatures were found. This inventory does not establish behavioral equivalence by itself.
