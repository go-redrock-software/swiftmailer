## Design

### Approach
Base `refactor/47-protect-sweego-http-contract` on !14 (`29044b7e`) so privacy, attachment, dispatcher/policy and response-boundary fixes remain intact. Establish a fresh focused Sweego mutation baseline using the isolated bridge runner. Protect externally observable request/response behavior and fix confirmed sender-name loss tracked in #52.

### Changes
- Public-send tests for exact API/JSON headers and HTTP options, using a real Guzzle MockHandler/history stack where middleware behavior matters.
- Exercise HTTP status boundaries and provider error `message`/`error` precedence, null/absent fallbacks and valid diagnostics; retain non-retryable ambiguous-response behavior from #50.
- Assert sent-message identifier, recipient count and exposed result/debug metadata; inspect the recipient-field mutant's observable difference before judging equivalence.
- Preserve `from.name="0"` while omitting null/empty names, with normal/Unicode controls and original-message restoration checks (#52). Reuse the existing role formatter if appropriate.
- Record each actual surviving mutant and its semantic assessment. No exclusion or threshold change without narrow evidence; do not pretend inherited or equivalent mutants were killed.
- Update the handoff and relevant release/API documentation.

### Acceptance Criteria
- Before/fixed evidence for sender `"0"` loss and behavior tests that kill genuinely different remaining request/response mutations.
- Fresh coverage and focused mutations execute with a temporary config using the isolated runner and normal inherited deprecation policy. Repository mutation profiles, baseline and 78/95 global thresholds remain unchanged.
- Exact payload/options and error/sent metadata expectations pass through public sends, preserving recipient policies, envelopes and privacy/attachments.
- Any remaining equivalent survivor is documented against the current code and runtime behavior, with no blanket exclusion.
- Focused/full PHP 8.3/8.5 suites, PHPStan, full style, strict Composer validation and final-head required CI pass. No live email or merge.

### Risks
The HTTP 300 boundary may now be redundant with #50's shared decoder, so a surviving boundary mutation can be equivalent in the current source. Guzzle adds Content-Type for the JSON option, but explicit Accept negotiation and http_errors behavior remain observable. Debug results are exposed by SentMessage even where the transport can fall back to the same recipient count. Optional CI prerequisites remain #38/#40/#45/#46 until !11 is integrated. Newly discovered unrelated defects will be tracked separately rather than silently changing this work's scope.
