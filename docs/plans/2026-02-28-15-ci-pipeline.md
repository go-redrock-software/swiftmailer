# CI Pipeline (GitHub Actions) -- Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Replace the outdated `.github/workflows/tests.yml` with a comprehensive CI pipeline that tests PHP 8.1-8.4, enforces code style, runs static analysis, and validates Composer configuration.

**Architecture:** The pipeline is a single GitHub Actions workflow file with four parallel jobs: `composer-validate`, `code-style`, `phpstan`, and `tests`. The `tests` job uses a matrix strategy across PHP 8.1, 8.2, 8.3, and 8.4. All jobs share a common Composer dependency caching strategy keyed on `composer.lock` hash. PHPStan requires a new `phpstan.neon.dist` config file and a `composer.json` dev-dependency addition since it is not currently declared.

**Tech Stack:** GitHub Actions, PHP 8.1-8.4, Composer, PHPUnit, PHP-CS-Fixer, PHPStan.

## Current State

- **Existing workflow:** `.github/workflows/tests.yml` -- outdated, targets PHP 8.0/8.1/8.3 (missing 8.2, 8.4; includes dropped 8.0), uses deprecated `actions/checkout@v2` and `nick-invision/retry@v1`, runs *all* test suites (including acceptance/smoke that need a mailcatcher service)

## Task 2: Create PHPStan configuration file

**File (new):** `/phpstan.neon.dist`

**Complete content:**
```neon
parameters:
    level: 5
    paths:
        - lib/classes
    excludePaths:
        - vendor
    reportUnmatchedIgnoredErrors: false
    ignoreErrors:
        # PSR-0 underscore naming conventions trigger false positives
        - '#Class Swift_[A-Za-z_]+ not found#'
```

**Rationale:** Level 5 is a reasonable starting point -- it checks for calling methods on mixed types, return type mismatches, and missing typehints without being overly strict on a legacy codebase. The `lib/classes` path is where all source lives. The ignore pattern handles PSR-0 autoloading edge cases.

## Task 3: Replace the CI workflow file

**File:** `/.github/workflows/tests.yml` -- **delete** this file.

**File (new):** `/.github/workflows/ci.yml`

**Complete content:**
```yaml
name: CI

on:
  push:
    branches: [master]
  pull_request:
    branches: [master]

permissions:
  contents: read

jobs:
  composer-validate:
    name: Composer Validate
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup PHP
        uses: shivammathur/setup-php@v2
        with:
          php-version: '8.3'
          tools: composer:v2
          coverage: none

      - name: Validate composer.json
        run: composer validate --strict --no-check-publish

  code-style:
    name: Code Style
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup PHP
        uses: shivammathur/setup-php@v2
        with:
          php-version: '8.3'
          extensions: mbstring, intl
          tools: composer:v2
          coverage: none

      - name: Cache Composer dependencies
        uses: actions/cache@v4
        with:
          path: vendor
          key: composer-style-${{ hashFiles('composer.lock') }}
          restore-keys: composer-style-

      - name: Install dependencies
        run: composer install --prefer-dist --no-interaction --no-progress

      - name: Run PHP-CS-Fixer (dry run)
        run: vendor/bin/php-cs-fixer fix --config=.php-cs-fixer.dist.php --dry-run --diff --verbose

  phpstan:
    name: PHPStan
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup PHP
        uses: shivammathur/setup-php@v2
        with:
          php-version: '8.3'
          extensions: mbstring, intl, iconv, openssl
          tools: composer:v2
          coverage: none

      - name: Cache Composer dependencies
        uses: actions/cache@v4
        with:
          path: vendor
          key: composer-phpstan-${{ hashFiles('composer.lock') }}
          restore-keys: composer-phpstan-

      - name: Install dependencies
        run: composer install --prefer-dist --no-interaction --no-progress

      - name: Run PHPStan
        run: vendor/bin/phpstan analyse --configuration=phpstan.neon.dist --no-progress

  tests:
    name: Tests (PHP ${{ matrix.php }})
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        php: ['8.1', '8.2', '8.3', '8.4']
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup PHP
        uses: shivammathur/setup-php@v2
        with:
          php-version: ${{ matrix.php }}
          extensions: dom, curl, libxml, mbstring, zip, intl, iconv, openssl
          tools: composer:v2
          coverage: none

      - name: Cache Composer dependencies
        uses: actions/cache@v4
        with:
          path: vendor
          key: composer-tests-php${{ matrix.php }}-${{ hashFiles('composer.lock') }}
          restore-keys: composer-tests-php${{ matrix.php }}-

      - name: Install dependencies
        run: composer update --prefer-stable --prefer-dist --no-interaction --no-progress

      - name: Run unit tests
        run: vendor/bin/simple-phpunit --testsuite="SwiftMailer unit tests" --verbose
```

**Key decisions:**
- `fail-fast: false` on tests so all PHP versions report results even if one fails
- Tests job uses `composer update` (not `install`) to test against latest compatible dependencies per PHP version
- Code-style and PHPStan jobs use `composer install` for deterministic dependency resolution
- Only the `SwiftMailer unit tests` suite is run (no acceptance/smoke/bug suites that need external services)
- Triggers only on `master` push and PRs targeting `master` (not on all pushes to all branches)
- Uses `actions/checkout@v4` and `actions/cache@v4` (current stable versions)
- Removed the deprecated `nick-invision/retry@v1` action -- Composer is reliable enough without retry wrappers
- Removed the `mailcatcher` service since we only run unit tests
- Removed the conditional `symfony/phpunit-bridge:^5.4` require since `composer.json` already declares `^4.4|^5.4`
- Permissions scoped to `contents: read` for security

## Task 5: Run `composer update` to regenerate lock file

After adding PHPStan to `composer.json`, run:

```bash
composer update phpstan/phpstan --no-interaction
```

This updates only the PHPStan package in `composer.lock` without touching other dependencies.
